# M2 安全采样、画像与定时刷新实施计划

- 状态：执行中
- 日期：2026-09-05
- 设计：`docs/superpowers/specs/2026-09-05-m2-safe-profiling-scheduling-design.md`

## 推进原则

- 按可部署纵向子切片推进，每个子切片独立测试、验收、提交并推送；
- 先建立不可绕过的授权与预算，再允许连接器读取业务表；
- 敏感字段失败关闭，任何任务、日志、审计和异常均不得携带样例原值；
- 画像绑定不可变目录快照，画像失败不得影响已发布元数据；
- 调度、取消、回收与重试以数据库状态和幂等键为正确性基础；
- PostgreSQL 与 MySQL 共享契约与业务规则，方言差异只存在于连接器内部。

## 子切片一：策略、计划与画像领域基础

状态：已完成并通过验收（2026-09-05）。验收记录见`docs/acceptance/M5-sampling-control-plane-acceptance.md`。

目标：建立默认关闭、可验证且可持久化的控制面，不读取业务数据。

1. 扩展枚举与领域模型，加入采样策略、扫描计划、画像状态、字段画像、样例及任务恢复字段；
2. 新增 Alembic 迁移与完整升级、回滚约束；
3. 定义采样预算、白名单、计划和画像响应契约；
4. 实现策略读取与更新 API，严格限制角色、范围和预算；
5. 实现计划的时区、每日/每周表达校验，但暂不自动投递；
6. 补充工作空间隔离、乐观锁、审计和默认零采样测试；
7. 运行质量门禁、迁移往返验证，记录验收后提交推送。

## 子切片二：敏感识别与方言无关画像契约

状态：已完成并通过验收（2026-09-05）。验收记录见`docs/acceptance/M5-sensitive-profiling-engine-acceptance.md`。

目标：输入有限行值后，能够确定性地产出无敏感原值的有界画像文档。

1. 定义 `ProfileDocument`、关系画像、字段画像和样例值对象；
2. 实现字段名称、数据类型和有限值三层敏感识别；
3. 实现身份证与银行卡校验、邮箱/电话/令牌识别和失败关闭；
4. 实现通用文本遮罩、Unicode 截断与 UTF-8 字节预算；
5. 实现样本空值率、近似基数、范围和文本长度统计；
6. 覆盖中文、Unicode、低基数敏感值、预算耗尽及原值泄漏测试；
7. 运行质量门禁并提交推送。

## 子切片三：PostgreSQL 与 MySQL 安全画像

目标：两个连接器均能在相同安全边界内读取白名单普通表并输出统一画像。

1. 扩展连接器协议，加入受控画像方法；
2. 从已发布目录解析允许关系与字段，不接受用户 SQL；
3. PostgreSQL 实现安全标识符引用、行数估计和有界只读查询；
4. MySQL 实现等价能力，保留现有 TLS、IP 复核和权限验证；
5. 禁止视图、二进制、大对象、空间和未知复杂类型进入样例；
6. 建立双数据库画像契约、查询超时和预算上限测试；
7. 使用 Compose 样例源完成真实读取验收并提交推送。

## 子切片四：画像任务与不可变快照绑定

目标：元数据发布后可靠创建独立画像任务，并原子发布画像结果。

1. 元数据快照发布事务根据冻结策略创建 `profile_scan` 任务与 Outbox；
2. Worker 解密凭据并调用连接器，任务消息不携带凭据；
3. 实现阶段、进度、心跳、终态短路和协作式取消；
4. 单事务替换目标快照画像与样例，失败时零部分结果；
5. 实现画像列表与字段详情 API；
6. 覆盖策略关闭、禁用中取消、重复投递、失败隔离和版本隔离；
7. 完成 API 到双数据库真实任务闭环并提交推送。

## 子切片五：定时刷新、回收与受控重试

目标：每日或每周计划能够在故障与重复投递下可靠运行。

1. 实现 IANA 时区和夏令时安全的下次执行时间计算；
2. 实现到期计划原子领取、计划槽幂等键和 Outbox 投递；
3. Celery Beat 加入计划领取和过期任务回收；
4. 实现瞬时错误最多两次重试、永久错误不重试；
5. 实现取消和显式重试 API 及审计；
6. 覆盖并发领取、重复计划槽、Worker 丢失、重试耗尽和时区边界；
7. 完成真实定时刷新、恢复验收并提交推送。

## 子切片六：M5 整体验收与文档

目标：证明安全、兼容、可靠性和可运维性满足设计完成定义。

1. 执行 PostgreSQL/MySQL 的默认关闭、白名单、敏感原值零落库和预算验收；
2. 执行超时、取消、重启、重复投递、重试与版本隔离验收；
3. 执行迁移升级、回滚、再升级；
4. 运行 Ruff、格式检查、严格 MyPy、全量后端测试、前端检查和生产构建；
5. 更新 README、ADR、项目日志、总计划状态和 M5 验收记录；
6. 检查敏感信息、未追踪文件和 Compose 健康后提交推送。

## M5 完成定义

管理员能够为 PostgreSQL 或 MySQL 配置默认关闭的表级采样授权和每日或每周刷新计划；系统只执行有界只读查询，敏感原值不会落库或泄漏；画像准确标注统计语义并绑定不可变快照；调度、重复消息、取消、超时和 Worker 故障均能得到幂等、可追溯处理，且全部质量与真实集成验收通过。
