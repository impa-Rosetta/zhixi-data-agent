# M8 评测中心实施计划

- 设计规格：`docs/superpowers/specs/2026-09-25-m8-evaluation-center-design.md`
- 执行原则：各切片独立测试、记录、提交；真实模型批量调用必须由用户针对当次预算另行批准
- 当前边界：不把 Docker 故障中的模拟运行冒充真实 PostgreSQL、DeepSeek 或中文 PDF 验收

## M8-E1：严格案例契约与确定性判定器

1. 在 `packages/evaluation` 定义案例集、案例、轮次、断言和观察结果的 Pydantic 严格契约。拒绝重复 ID、空轮次、未知断言、不匹配的类别配额、超大文本和非合成数据源标记。
2. 提供规范化序列化、SHA-256 摘要和只读加载器。案例集版本和内容摘要进入每次运行记录；已有版本不可被静默覆盖。
3. 实现不依赖模型的判定器：结构化意图、语义绑定、工具、状态、数值与 Evidence/Validation 一致性、安全阻断；语言质量不进入确定性总分。
4. 测试通过、失败、未执行和基础设施错误的分母规则；覆盖数值容差、伪拒绝、丢失 Evidence、跨案例污染和恶意 JSON。

验收：无需 Docker 或 DeepSeek 可运行；Ruff、严格 MyPy、Pytest 全绿；错误码稳定，案例摘要确定性。

## M8-E2：140 组版本化黄金集与离线执行

1. 使用项目合成制造数据和已发布语义建立 60 标准、20 多轮、20 歧义、20 异常、20 安全场景，人工核对预期和来源。
2. 将离线适配器接入现有 Agent 路由、会话、工具和验证入口，FakeGateway 只替代模型响应；不得复制简化版 Agent。
3. CI 生成机器可读 JSON、分类汇总和安全失败清单；本阶段只发布离线回归数字，不标注为真实 DeepSeek 准确率。

验收：类别配额由加载器强制；140 组均有可执行断言，失败可定位到案例与运行；安全失败不可被平均值掩盖。

## M8-E3：持久化、权限、API 与界面

1. 新增 EvaluationRun、EvaluationCaseResult、迁移与工作空间索引；冻结案例集摘要、数据/语义/模型/工具版本及预算。
2. 新增默认拒绝的评测读/运行权限、事务 Outbox、审计和幂等创建；案例条件认领、过期恢复、取消及未知计费暂停。
3. API 提供案例集元数据、运行列表/详情/创建/取消及逐案例结果；界面区分离线和真实轨道，展示覆盖率、通过率、失败回链与预算状态。
4. 测试跨工作空间、撤权、并发认领、重复投递、刷新恢复、390px 与键盘操作。

验收：权限矩阵、迁移往返、API 契约、前后端全量测试和真实浏览器通过；不泄露原始企业数据或供应商请求。

## M8-E4：人工触发的真实模型基准

1. 管理员选择合成数据快照、案例子集、模型版本和调用/token/时长上限，界面二次确认；CI 和定时任务均不得自动发起。
2. 服务端逐调用预留预算并持久化实际 usage；不确定是否到达供应商的调用标记 `usage_uncertain`，暂停而非盲目重投。
3. 先用少量案例做真实模型验收，再在单独授权的预算内做完整批次；语言质量人工复核、确定性事实断言保持独立。

验收：有真实 API 调用和费用记录、预算达到上限停止、重复投递不重复计费；最终按总设计阈值记录结果，未达标不标记完成。

## 后续阶段

- M8-01：独立无网络、无凭据、非 root、限资源的一次性沙箱，只有预注册工具无法完成的高级分析才进入；
- M9：性能、安全、备份恢复、迁移回滚、部署手册、真实演示及比赛材料。
