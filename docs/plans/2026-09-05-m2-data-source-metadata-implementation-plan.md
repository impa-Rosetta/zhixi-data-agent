# M2 数据源接入与元数据发现实施计划

- 状态：执行中
- 日期：2026-09-05
- 规格：`docs/superpowers/specs/2026-09-05-m2-data-source-metadata-design.md`

## 推进原则

- 采用可部署纵向切片，每个切片独立完成实现、测试、迁移、文档、提交和推送；
- 先以PostgreSQL形成真实闭环，再通过连接器协议加入MySQL，不在业务服务中散落方言判断；
- 所有外部连接默认不可信，网络策略、只读校验、超时和资源限制必须先于扫描；
- API、任务载荷、日志、审计和测试失败信息不得包含明文凭据；
- 不为演示伪造任务进度、元数据、画像或Agent结果。

## 切片一：领域模型、密钥与网络策略

状态：已完成并通过验收（2026-09-05）。验收记录见`docs/acceptance/M2-data-source-foundation-acceptance.md`。

目标：建立数据源安全配置的持久化边界，不连接外部数据库。

1. 扩展`packages/platform_core/models.py`，加入数据源、密文、网络策略、扫描任务、outbox、快照及目录核心实体；
2. 新增Alembic迁移`20260905_0003`，为工作空间隔离、活动任务和快照版本建立约束与索引；
3. 在Settings中加入数据源主密钥和默认网络策略配置，生产环境拒绝开发密钥；
4. 新建Secret Provider，使用AES-256-GCM完成数据密钥与凭据两层加密、AAD绑定和密钥版本；
5. 新建Network Policy，完成主机校验、IP分类、CIDR/端口规则和解析结果复核；
6. 增加单元测试，覆盖加密篡改、跨资源替换、错误密钥、IPv4/IPv6、云元数据地址和白名单；
7. 更新`.env.example`、ADR、项目日志和切片验收记录；
8. 运行全量质量门禁、真实PostgreSQL迁移与回滚检查后提交推送。

## M2完成定义

管理员能够通过产品界面安全接入PostgreSQL和MySQL，只读验证与网络策略不可绕过；系统能够异步生成版本化目录、受限脱敏画像和准确结构差异；失败与重启不会污染当前快照或泄漏凭据；关键路径具备自动化测试，完整容器栈和浏览器流程通过验收。
