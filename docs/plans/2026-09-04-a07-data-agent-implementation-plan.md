# A07 企业数据智能问析 Agent 实施计划

- 状态：执行中（M0、M1、M2已验收，当前进入M3；详见`docs/project-status.md`）
- 日期：2026-09-04
- 设计依据：`docs/superpowers/specs/2026-09-04-a07-data-agent-design.md`
- 原则：纵向闭环优先、测试先行、每阶段可部署、每项决策留痕

## 1. 实施策略与完成定义

项目不按“后端写完再做前端，最后接模型”的横向方式开发，而按可运行的纵向切片推进：

```text
工程基线 → 身份与空间 → 数据源与元数据 → 语义与指标
→ 查询安全与执行 → Agent运行时 → 问析工作台
→ 验证与证据 → 分析/图表/报告 → 评测/安全/运维 → 比赛交付
```

任务只有同时满足实现、测试、类型检查、接口契约、错误和权限路径、迁移配置、文档及必要ADR更新，且不降低Agent既有评测指标，才算完成。

## 2. M0：工程与质量基线

### M0-01 Monorepo

- 建立`apps/web`、`apps/api`、`apps/worker`、`apps/sandbox`；
- 建立`packages/agent-core`、`toolkit`、`semantic-model`、`query-engine`、`analysis-engine`、`model-gateway`和`shared-contracts`；
- 提供统一README、环境模板和开发命令。

验收：全新环境一条命令启动Web、API、PostgreSQL、Redis、Worker和MinIO，健康检查全部通过。

### M0-02 质量门禁

- 配置Ruff、Pyright、Pytest、ESLint、TypeScript strict、Vitest和Playwright；
- 建立格式、类型、测试、迁移、契约、安全扫描和镜像构建CI。

验收：故意引入类型错误或失败测试时CI必须失败。

### M0-03 基础设施

- Docker Compose、Alembic、结构化配置、Secrets接口；
- 服务健康检查、结构化日志、数据库迁移和版本信息。

验收：配置缺失时快速失败且不泄漏秘密；迁移可从空库重复执行。

## 3. M1：身份、工作空间与权限

### M1-01 认证

实现登录、刷新令牌、退出、Argon2密码哈希、会话撤销和认证限流。

### M1-02 工作空间

实现空间、邀请、成员和系统管理员、空间管理员、数据管理员、分析用户、审计员五类角色。

### M1-03 Policy Engine

实现覆盖数据源、Schema、表、字段、行级范围、工具和导出的统一权限请求模型。

验收：跨空间访问全部拒绝；任何工具无法绕过Policy Engine；权限矩阵测试完整。

## 4. M2：数据源与元数据

### M2-01 数据源生命周期

状态：已完成并验收。

实现PostgreSQL/MySQL连接、加密凭证、只读校验、健康状态、连接池和启停。

### M2-02 元数据扫描

状态：已完成并验收。

扫描Schema、表、视图、字段、类型、注释、主外键、索引、行数估计和更新时间，生成版本化快照与差异。

### M2-03 安全采样

状态：已完成并验收。详细设计、实施与证据见`docs/superpowers/specs/2026-09-05-m2-safe-profiling-scheduling-design.md`、`docs/plans/2026-09-05-m2-safe-profiling-scheduling-implementation-plan.md`及`docs/acceptance/M5-safe-profiling-overall-acceptance.md`。

采集空值率、唯一值数、数值/日期范围、高频值和受限样例；敏感字段默认不采样。

### M2-04 数据源管理页面

状态：已完成并通过整体验收（2026-09-07）。证据见`docs/acceptance/A5-m2-overall-acceptance.md`。

实现连接向导、扫描进度、结构浏览、字段画像和结构变化提示。

验收：管理员完成连接到查看元数据的全流程；错误凭证、超时、中断、权限不足和重复扫描均受控处理。

## 5. M3：质量语义模型与样例数据

### M3-01 标准语义模型

定义工厂、车间、产线、产品、工单、批次、工序、设备、检验和缺陷等核心概念，具备版本、状态和审计。

### M3-02 指标中心

实现公式、聚合、单位、维度、时间粒度、约束、别名、版本和发布流程。首批提供15–20个产量、质量、缺陷和设备关联指标。

验收：总体比例使用ratio-of-sums；缺字段或分母不合法的指标不可发布。

### M3-03 物理映射

实现表、字段、关系、维度值映射，以及模型候选、置信度、人工确认和版本化发布。

### M3-04 合成数据集

生成可复现的质量数据，预埋异常批次、设备故障后质量波动、缺陷集中、样本量偏差、缺失和延迟到数。

验收：每个模式有确定性预期答案；固定种子可重建相同数据。

### M3-05 映射工作台

实现候选映射、歧义确认、关系编辑、指标可行性和发布检查。

验收：同一语义模型可适配标准库、改名库和缺字段库。

## 6. M4：查询编译、安全与执行

### M4-01 语义查询协议

定义指标、维度、过滤、时间、比较、排序和限制的严格Schema。

### M4-02 查询编译器

根据指标、映射和连接关系生成PostgreSQL/MySQL参数化SQL，覆盖趋势、Top N、周期比较和多表关联。

### M4-03 SQL安全引擎

用SQLGlot实施只读、多语句、系统表、对象权限、危险函数、行数和成本策略。

### M4-04 查询执行器

只接受已验证查询ID，使用只读事务，支持超时、取消、脱敏、结果限制和证据记录。

### M4-05 探索性SQL

实现LLM草案、校验、错误诊断、最多两次修正和探索性可信标签。

验收：CTE隐藏写操作、注释混淆、方言绕过、笛卡尔积和资源消耗用例均被正确处理；安全失败不能由模型绕过。

## 7. M5：Agent核心闭环

### M5-01 Model Gateway

实现DeepSeek V4 Pro的结构化生成、工具调用、流式输出、思考模式、超时、重试、降级和用量记录。业务模块不得引用供应商SDK。

### M5-02 状态与检查点

实现AnalysisRun、Step、Artifact、Evidence、Validation、Budget和Checkpoint持久化。

### M5-03 意图与语义绑定

解析领域、任务类型、指标、维度、过滤、时间、比较、输出、歧义和置信度，并绑定已发布语义版本。

### M5-04 Planner

输出声明式AnalysisPlan和步骤依赖，禁止直接嵌入未受控代码实现。

### M5-05 Tool Registry

实现工具版本、能力、输入输出Schema、权限、风险、超时、重试、幂等和缓存元数据。

### M5-06 LangGraph执行图

实现理解、绑定、计划、确认、执行、验证、重规划、呈现和失败状态，每个分支有退出条件和预算。

### M5-07 多轮上下文

结构化保存目标、指标、过滤、数据集和产物引用，支持“只看A线”“再和上月比较”等计划变更。

验收：服务重启可恢复；重复消息不重复执行关键步骤；低置信度触发澄清；可信指标不能被模型临时改写。

## 8. M6：智能问析工作台

### M6-01 SSE事件流

实现任务、意图、绑定、计划、步骤、工具、验证、确认、回答和结束事件，断线按事件序号恢复。

### M6-02 对话与任务

实现问题、多轮消息、实时进度、取消、重试、确认和失败恢复。

### M6-03 结果与证据

实现指标摘要、数据表、图表、结论、警告、可信等级和数字到证据的定位。

### M6-04 技术详情

按需展开计划、口径、SQL、工具、耗时、模型和语义版本；默认业务界面保持简洁。

验收：刷新不丢运行状态；长任务不阻塞页面；图表失败时表格与分析仍可用。

## 9. M7：验证、分析、图表和报告

### M7-01 三层验证

- 结构：Schema、计划依赖、SQL对象和图表字段；
- 数据：空值、值域、分母、样本量、时间连续、重复和粒度；
- 语义：口径、问题覆盖、周期、数字引用、百分点和因果措辞。

验收：预埋错误被对应验证器发现，未验证答案不得完成。

### M7-02 分析工具

实现描述统计、同比环比、趋势、Top N、相关性、缺失分析和Isolation Forest异常检测。

### M7-03 图表

定义受限ChartSpec并转换为ECharts，支持折线、柱状、散点、分布和热力图。

### M7-04 报告

从已有分析产物组装Markdown、HTML和PDF，包含问题、范围、指标、图表、结论、限制和证据，不重新计算指标。

## 10. M8：沙箱、评测与可观测性

### M8-01 Python沙箱

实现无网络、无数据库凭证、非root、只读输入、资源限制和一次性容器。

### M8-02 黄金评测集

建立至少140组场景：60标准问题、20多轮、20歧义、20异常和20安全攻击。

### M8-03 评测中心

展示意图、绑定、工具、SQL结果、数字一致性、安全拒绝、延迟和成本。

### M8-04 可观测性

接入OpenTelemetry、Prometheus和结构化日志，覆盖Agent、模型、工具、SQL和队列。

验收：可从错误答案追溯到具体模型调用、工具、输入摘要和验证结果；沙箱越界、网络、超时和内存超限均失败并留痕。

## 11. M9：产品加固与交付

- 性能与并发：连接池、缓存、Worker队列和负载测试；
- 安全测试：越权、Prompt Injection、SQL绕过、数据泄漏、导出、凭证和沙箱；
- 备份升级：数据库、对象存储、配置的备份恢复及迁移回滚；
- 产品文档：部署、运维、管理员、接入、指标、用户、API和排障；
- 比赛材料：项目概要、详细方案、PPT、演示脚本、测试报告、过程记录、业务知识和数据资源说明。

## 12. 阶段质量阈值

首次基准运行后将阈值固化为CI门禁：

| 指标 | 目标 |
|---|---:|
| 标准问题意图准确率 | ≥95% |
| 可信指标绑定准确率 | ≥95% |
| 语义查询执行成功率 | ≥99% |
| 标准问题结果正确率 | ≥95% |
| 答案数字证据一致率 | 100% |
| 未授权数据访问阻断率 | 100% |
| 危险SQL阻断率 | 100% |
| 多轮上下文保持成功率 | ≥90% |
| 可恢复任务恢复成功率 | ≥99% |

安全指标不得以平均值掩盖单个严重失败。

## 13. 首个开发迭代

第一迭代仅完成M0，并为M1建立接口骨架。交付：

- 可运行仓库和一键启动环境；
- Web及API健康页面；
- PostgreSQL迁移；
- Redis、Celery、MinIO连接验证；
- 基础CI和本地质量命令；
- 开发说明和环境模板；
- ADR更新及M0验收记录。

M0验收通过后才进入身份与工作空间，避免在不稳定底座上堆叠业务代码。

## 14. 变更控制

- 重要选择更新`docs/decisions/README.md`或新增独立ADR；
- 每个里程碑结束更新项目日志和风险清单；
- 新需求必须标注里程碑、依赖和验收标准；
- 绕过权限、验证、测试或审计的临时实现不得进入主分支；
- 结构性变化先更新规格并确认，再调整本计划。
