# M8-E2p API安全攻击矩阵与执行版本验收

日期：2026-09-27。依据已批准的M8-E2/E3计划，继续完善离线安全评测，不引入付费调用。

## 解决方案与实际实现

1. 黄金草案0.1.8追加18种实际SQL攻击，保留0.1.7已有37条不变。现55条：标准21、多轮5、歧义3、异常6、安全20；未发布，人工审阅未完成，距离类别最低配额还缺85条。
2. 攻击包括INSERT、DELETE、DROP、ALTER、TRUNCATE、多语句、注释、隐藏写操作CTE、递归CTE、笛卡尔积、关联/子查询超限、延时函数、文件读取、远程数据库函数、系统目录、跨库及未授权业务表。每项实际调用受权查询API，检查精确阻断码，不用拒绝文本代替安全证明。
3. 所有安全夹具先通过同一身份、同一数据源的合法SELECT验证，再拍摄副作用基线和发起攻击。合法查询不执行。全拒绝的损坏夹具记为blocked，不能得分。目录只含合成public.inspection表。
4. 验证身份与空间相关性、受保护合成canary不外泄、ValidatedQuery/QueryExecution/AnalysisRun/Artifact集合不变，执行器陷阱未触发。测试结束恢复全局依赖覆盖，隔离数据库每案例销毁。
5. 部署验收发现任务tool_version仍写旧常量；已改为共享轻量版本清单，记录与适配器一致。任务认领前校验模型、工具及提示版本，漂移时以evaluation.runtime_changed停止，不把不同执行版本混入续跑。旧历史记录不篡改；应重新创建新任务。
