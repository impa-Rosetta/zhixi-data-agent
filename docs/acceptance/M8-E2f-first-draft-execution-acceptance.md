## 实现与结果

新增版本化草案适配器及可重复执行入口，加载现有 5 个案例草案，复用批量执行器、产品 create_run / run_analysis / get_run_view 和实际澄清观察器。每次澄清执行使用独立内存数据库和固定 FakeGateway 响应，读取持久化的实际 Agent 问题及运行状态；没有复制简化 Agent，没有替换 metric_executor。

适配器只支持固定 ID、固定问题和 ambiguity 类别的首个澄清案例。遇到其他问题、数值或趋势案例时，不创建产品 Run，返回前置条件不满足。Docker 引擎当前不可达，真实查询夹具和其适配器未就绪，不能据此声称数值或多轮趋势通过。

本次实际批次：总计 5 例，1 例通过、4 例 blocked、0 例业务失败，覆盖率及全案例通过率均为 20%。已评估通过率为 100% 只是单个固定模型响应下澄清案例的局部比例，不代表 DeepSeek、140组案例或整个 Agent 的准确率。案例集仍 published=false。

报告的 synthetic_dataset_id / semantic_version 来自案例声明，不代表本轮装载了该业务数据或语义模型。运行使用隔离 SQLite 平台数据库；未装载制造质检业务数据，亦没有发布语义模型。Run ID 仅用于关联该次离线测试过程，夹具已清理，不是可在产品页面打开的生产任务。

## 使用

在项目根目录运行：

```powershell
.venv/Scripts/python.exe -m scripts.evaluate_offline --output .tmp/evaluation/draft-report.json
```

输出文件必须尚不存在，避免覆盖既有证据。全部案例通过时退出码为 0，存在 blocked、未执行、环境错误或失败时退出码为 1。本次退出码 1 是如实标记未完成，不是脚本崩溃。

实际报告：`docs/acceptance/evidence/M8-E2f-2026-09-27-draft-offline.json`。
