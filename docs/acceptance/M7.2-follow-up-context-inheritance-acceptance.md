## 已交付能力

- 新增严格 `FollowUpDecision`，关系仅允许 `continue`、`refine`、`explain`、`compare`、`switch_topic`；
- “按月”“与上月相比”“为什么”“继续”和显式换题优先由确定性规则分类，不消耗模型调用；
- 其他表达通过 Model Gateway 返回严格结构化候选，额外字段、SQL、代码、工具名和权限声明不能进入契约；
- 当前轮真正开始执行时才读取最新持久化上下文，排队消息不会继承排队时的过期结果；
- 完成轮只投影指标、维度、过滤、比较、粒度以及已验证 Artifact/Evidence 引用，大小上限保持 16 KiB；
- 未验证结果、连接信息、凭据、SQL、内部推理和跨工作空间对象不会进入会话上下文；
- `continue/refine/compare` 以旧 Intent 为受限修订基础，`switch_topic` 清除旧 Intent 和冲突上下文；
- 显式时间追问的确定性补丁在模型修订后再次落地，模型不能丢弃“按月/上月”等已验证约束；
- “月份/周/年份”等业务粒度按已选指标的 `supported_dimensions` 绑定唯一兼容时间维度，计划显式携带 `time_grain`；
- `explain` 使用受控 `analysis.describe` 引用上一轮已验证结果，不重新查询数据源，也不覆盖原查询结果引用；
- 关系不确定时，Agent 在当前 Turn 中用自然语言询问用户；
- 新增 `run.follow_up_classified` 与 `run.topic_switched` 审计事件。
- 新增受控 `small_talk` 意图，短寒暄、在场确认、感谢和告别由本地确定性处理，零模型调用、零数据查询；
- 寒暄作为非业务插曲保留原会话指标、筛选、粒度与已验证结果引用，后续追问继续绑定寒暄前最近一次业务 Intent；
- 寒暄仍生成独立 Plan、`system.small_talk` ToolCall、assistant_message Artifact、conversation_scope Validation 和完成事件，但不生成数据 Evidence；
- 仅匹配完整短句，“你好，我想看不良率”等包含业务请求的消息继续进入正常 Agent 理解流程。
