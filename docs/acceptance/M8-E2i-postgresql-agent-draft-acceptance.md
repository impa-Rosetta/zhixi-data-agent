# M8 E2i：真实 PostgreSQL Agent 查询与多轮草案评测

日期：2026-09-27

## 本轮实现

新增 PostgreSQL 离线适配器和独立运行入口，复用已有批量评分器。只允许固定的合成库端点 `source-evaluation:5432/factory_demo`，不接受生产数据库地址，不挂载 `.env`，不调用模型供应商。

每道数据案例生成独立的 `eval_<UUID>` 平台 schema：真实扫描公开合成库目录，保存目录快照与加密只读连接凭据，建立检验数量、缺陷数量、检验时间的确认映射，经现有语义模型服务发布。Agent 通过现有 create_run/run_analysis 执行；不注入 metric_executor，查询编译、SQL 门禁、只读数据库执行、产物、证据与校验都使用现有产品实现。仅模型响应固定，因此这证明执行链路，不证明真实模型意图准确率。

多轮案例调用 create_conversation 和 send_conversation_message，保持一个 conversation、两个有序 turn 和两个不同 run。第一轮完成后通过现有投影服务同步上下文，再处理追问。固定夹具参考时间为 2026-09-27，避免“最近三个月”随测试日期漂移。两轮均须得到 2026 年 7/8/9 月三个时间点及 1.75%、2.75%、3.00%；重复月份、缺行、非法时间、非有限数字、错误数值或截断均不能通过。

歧义案例沿用已有 SQLite 澄清适配器，要求真正向用户展示澄清问题且不调用数据工具。未支持的案例不会被伪装为通过。

## 复验方法与边界

在独立测试 PostgreSQL 容器及网络运行时，使用既有 worker 镜像，分别只读挂载 apps、packages、scripts、evaluations 到 /app 下的同名目录，再执行 `python -m scripts.evaluate_postgres_draft`。`--suite-version` 仅支持 0.1.0 与 0.1.1，默认 0.1.1；`--output` 仅创建新文件，已有报告会在打开数据库前被拒绝。若保存报告，单独挂载报告目录，不挂载项目根目录或环境文件。

本轮完成首批 5 条草案的可复验执行，不是 140 条正式案例，也不是 DeepSeek 实测，更不是 M8 整体完成。下一阶段仍需扩展异常/安全案例、持久化评测 API 与页面、真实模型预算控制。M7.7 报告存储及中文 PDF 部署验收、M9 仍需继续完成。
