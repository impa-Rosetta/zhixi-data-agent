## 复核

- 本机 Node.js `v24.15.0`、npm `11.12.1`；GitHub CI 使用 Node.js 22，环境不完全相同。
- `apps/web` 的 `npm run lint`、`npm run typecheck` 和 `npm run build` 通过。生产构建生成单独的 `AnalysisChart` 代码块（约 588.53 kB），构建对大于 500 kB 的块给出警告。
- 默认 `npm run test` 出现 70/71：`AnalysisResultPanel.test.tsx` 的图表附件断言达到 5 秒测试时限。单独执行该文件为 7/7，通过时间约 1.96 秒。
- `npm run test -- --maxWorkers=1` 为 71/71，约 23.61 秒；jsdom 创建 20 次，占跟踪时间的 63%。执行中有 `HTMLCanvasElement.getContext` 未实现提示。这一次串行通过不能证明默认并行门禁稳定。
- `AnalysisChart.test.ts` 已用 ECharts 服务端 SVG 渲染验证三个月份及图例文字，但这不是浏览器页面的真实绘制验收。现有 M6 浏览器验收可检查已完成分析和证据；尚未断言图表 SVG 在页面中可见。

## 判断及边界

当前证据更符合重型图表模块导入与 jsdom 并行资源争用导致的测试超时；尚不能据此断言用户浏览器生图故障，也不能排除浏览器侧绘制缺陷。不能仅通过提高全局超时或只运行串行测试宣称问题关闭。

候选修复：页面组件单测隔离 ECharts 重型加载，同时保留真实 SVG 渲染测试，并补充页面浏览器图表可见性验收。该方案待确认，本文不包含代码修改或验收结果。
