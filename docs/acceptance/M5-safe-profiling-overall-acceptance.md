- 日期：2026-09-05

- 范围：M2-03安全采样，以及画像任务、定时刷新和任务恢复支撑能力

## 产品能力结论

- PostgreSQL 16.4与MySQL 8.4共用结构化画像契约、确定性敏感识别、脱敏规则和多层预算；
- 采样默认关闭，只允许管理员授权已发布目录中的普通表，任务不接受用户SQL；
- 元数据先发布，画像再以独立任务绑定不可变快照，画像失败不影响目录可用性；
- 凭据只在Worker执行边界解密，任务、Outbox、审计、API和画像结果均不携带凭据；
- 每日/每周IANA时区计划支持计划槽幂等领取、事务Outbox、取消、自动恢复和显式重试；
- 画像列表与字段详情API能够直接供后续语义模型、Agent规划器和数据源管理页面消费。

## 双数据库真实闭环

在全新平台租户上通过真实HTTP API与后台Celery服务依次完成：

1. 创建PostgreSQL/MySQL数据源并异步验证只读连接；
2. 自动发布首版目录，确认`profiling_status=disabled`；
3. 通过版本化API授权`production_orders`并冻结2行/2值/8192字节/3秒预算；
4. 手动发布第二版目录并由Outbox自动派生画像任务；
5. Worker分别连接真实样例源并原子发布字段画像；
6. 通过画像API读取结果并验证预算。

结果：

- PostgreSQL：6个字段画像、11个样例、83字节；
- MySQL：6个字段画像、11个样例、77字节；
- 两个任务均成功，`budget_exhausted=false`；
- 数据库检查确认任务参数、Outbox和审计中的验收凭据命中数均为0；
- 明显邮箱/长数字敏感样例命中数为0，单个已保存样例最大32字节。

真实定时刷新验收中，Celery Beat领取到期计划后创建并完成`scheduled`元数据与画像任务，计划被推进至未来。隔离注入的失联任务从第2次尝试恢复后正确进入第3次失败终态，错误码为`scan_job.worker_lost`。验收租户、用户和数据源随后已清理。
