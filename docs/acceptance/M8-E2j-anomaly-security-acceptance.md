# M8 E2j：空值解释、异常数据与安全 API 评测

日期：2026-09-27

## 用户可见改进

单值指标为 SQL NULL 时，不再回答“不良率为空值”，而是说明当前无法计算、不能当作 0；提示可能没有有效数据或分母为零/缺失，并明确仅凭当前结果不能确定原因。用户可扩大时间范围或查询检验数量等基础指标。此时不生成数字答案声明；真正的数值 0 仍正常回答，空行结果仍提示没有找到数据。

本轮不增加自动诊断查询，所以不能保证自动区分空集、零分母与字段缺失。后续可通过独立基础指标查询进一步诊断，不在展示层猜测原因。

## 新增草案案例

v0.1.2 保留 v0.1.1 的前五条案例原样，新增四条：

1. 无匹配月份：公开合成表没有 2000 年 1 月记录，经真实查询链路返回单值 NULL。
2. 零分母：在本案例独立临时 schema 建立仅包含一条检验数量为零的合成表，仍使用现有 SQL 编译与只读执行器；NULLIF 防除零后返回 NULL。只读账号仅获得临时 schema 使用和该表 SELECT 权限，不改 public 表。
3. 越权空间 API：真实 compile 路由使用仅属于本空间的合成身份访问另一个空间，应返回 403，不泄露保护标记，不写入查询、执行、Agent Run 或 Artifact。
4. 写入 SQL API：真实 validate-exploratory 路由接收固定 UPDATE，必须返回 422/query.read_only_required；陷阱执行器记录任何越过门禁的调用，不能只靠拒绝文字评分。

两条异常案例还校验真实 NULL 产物、非截断结果和最终自然语言解释，不能用假 0 或空数组混过。两条安全案例使用独立 SQLite 平台夹具和实际 API 路由，没有访问真实数据库，不向数据库发送危险 SQL。它们属于 system_gate，不等同于真实模型面对恶意问题时的 agent_behavior。

## 方案与隔离

沿用 PostgreSQL 合成源和按案例隔离 schema 的执行适配器；新增安全适配器复用现有 SystemGateProof，保留身份、空间、前后状态和执行器调用证明。API 依赖覆盖及执行器陷阱仅在单个串行测试上下文生效，退出时恢复此前状态，不改生产权限或 SQL 门禁。

由于新增了零分母专用数据，最终草案使用独立的 `synthetic-quality-source-init-anomaly-v2` 数据集标识，避免误认为与旧版只有公开 source-init 数据的基准完全相同。旧版 0.1.0、0.1.1 文件与报告不覆盖；正式套件仍为 published=false，尚需团队人工审阅。
