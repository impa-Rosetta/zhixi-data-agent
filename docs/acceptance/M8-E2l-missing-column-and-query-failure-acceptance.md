# M8-E2l 缺字段回归与查询失败防伪验收

- 日期：2026-09-27
- 范围：在已批准 M8 离线黄金集内增加源表字段消失场景，并修复 Agent 将失败查询包装成可信空结果的问题。
- 结论：隔离合成 PostgreSQL 全集 16/16、受权 API/Outbox/Worker 16/16；这仍是未发布的确定性离线草案，不是 DeepSeek 实测或 140 组正式黄金集。

## 发现与修复

1. 0.1.4 保留 0.1.3 的全部 15 条，新加一条异常案例：发布语义映射之后，只在该案例拥有的临时 schema 删除 `defect_quantity`。真实 Agent 沿既有语义解析、编译、安全门禁和只读执行路径提问“2026年9月的不良率是多少？”。
2. 修复前的实际运行：查询服务把数据库执行失败记录为 `failed`，但 Agent 未检查该状态，读取空列/空行并生成“没有找到数据”的可信结果、证据及通过验证。这不是空数据，而是数据源结构漂移；原行为会误导用户。
3. 修复后，Agent 仅在查询执行状态为 `succeeded` 且具有证据摘要时接受结果；否则以稳定的 `query.execution_failed` 失败，给出自然语言“没有产生可用结论”，不创建查询结果、证据、通过验证或数字声明。原始数据库异常详情不展示给用户。
4. 该异常案例的适配器核验真实运行处于失败终态、存在错误码、用户看到了失败提示、无结果/证据/验证/数字声明。仅返回“无法回答”的文本或伪造观察对象不能算通过。
