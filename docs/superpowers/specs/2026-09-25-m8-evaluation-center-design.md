# M8 评测中心设计规格

- 日期：2026-09-25
- 阶段：M8-02 黄金评测集与 M8-03 评测中心
- 状态：待用户审阅，尚未实施
- 上游：M1 权限、M3 版本化语义模型、M4 可信查询、M5 Agent、M7 连续会话与证据
- 不在本规格内：M8-01 一次性 Python 沙箱、M8-04 全链路观测、M9 性能与部署加固

## 1. 目标与边界

评测中心回答三个问题：Agent 是否把问题交给正确的能力；是否产生正确且可追溯的结果；是否拒绝越权与危险操作。它不把流畅措辞当作事实正确性的替代品。首版覆盖至少 140 组场景，沿用总设计的 60 组标准问题、20 组多轮、20 组歧义、20 组异常数据和 20 组越权或攻击场景。所有标准案例只引用项目的合成制造质量数据、可公开的语义定义和明确的测试身份，不纳入用户企业的原始表、凭据或聊天记录。

执行分成两个互不混淆的轨道：

1. **离线回归**：CI 中使用固定数据、固定语义版本和 FakeGateway/录制的最小结构化模型输出，复用生产 Agent 的路由、计划、工具和验证代码。它验证确定性契约，不声称衡量真实 DeepSeek 的语言能力。
2. **真实模型基准**：只有具备评测管理权限的用户手动创建，使用已发布的测试工作空间与合成数据，冻结模型、提示模板、工具和语义版本。显示并强制执行调用次数、token 和时长上限；不自动进入 CI，不因网页刷新重复发起。

两个轨道分别展示覆盖率、通过率、失败案例和版本变化，不能把离线通过率合并为真实模型准确率。真实模型基准的费用只有配置了经确认的单价时才显示估算值；实际调用量始终按网关返回的 usage 记录。

## 2. 组件与数据流

新增 `packages/evaluation` 作为无 Web、无供应商依赖的评测领域模块：严格案例契约、案例集载入与摘要、确定性判定器、聚合器。案例集以仓库版本化 JSON 文件保存；加载时校验 schema、唯一 ID、类别配额、禁止敏感字段和引用版本，计算内容 SHA-256。案例执行器在独立 Worker 队列/任务中驱动现有会话与 Agent 入口，不复制一套“简化 Agent”。生产入口仍通过已有 Policy Engine、工具注册表和 SQL 安全门禁。API 提供受权的案例集元数据、运行创建、列表、详情与案例结果；前端增加面向管理员/审计查看的评测中心页面。

```text
版本化案例集 + 合成数据快照
          ↓ 冻结摘要与运行预算
评测运行 → 逐案例 Agent/会话执行 → Artifact、Evidence、Validation、Trace 引用
          ↓ 确定性判定器
案例结果与聚合指标 → 评测中心 / CI 门禁 / 失败回溯
```

持久化 `EvaluationRun`、`EvaluationCaseResult` 两种核心记录。运行记录保存工作空间、案例集摘要、执行轨道、模型和提示/工具/语义版本、预算、状态、开始/结束时间、总用量及创建人；案例结果保存案例 ID、尝试号、执行状态、各断言结果、时延、模型/工具计数、token、原有 Run/Evidence/Validation 引用和安全化错误码。测试身份使用受限合成工作空间；真实企业工作空间不得被评测器自动遍历。案例、运行和结果都按工作空间隔离，报告正文、原始 SQL 结果、模型推理内容和密钥不复制到评测表。

## 3. 案例契约与黄金集

每个案例包含稳定 ID、类别、版本、输入轮次、前置合成数据/语义版本、测试角色、预期关系与允许工具、预期结构化结果或安全拒绝、数值容差和断言集合。多轮案例以一条会话中的有序消息为一个场景，不能拆成独立单轮后宣称保持上下文。歧义案例必须明确应提出的问题或候选范围；异常数据案例包含空集、缺字段、极值、零分母、时间边界和数据源故障；安全案例包含跨空间、Prompt Injection、危险 SQL、未授权目录与敏感字段探测。每类案例要同时有正例和失败路径。

前 140 组由人工审阅的确定性预期构成，不能靠模型自身生成答案又由同一模型评分。PR 新增或修改案例时记录原因和预期来源；既有案例集不可就地覆盖已完成运行所引用的摘要。案例集版本升级后可与旧基准并列比较，但不同数据/语义快照的通过率必须显著标注为不可直接比较。

## 4. 判定、指标与门禁

断言在结构化产物上运行，而不是关键词匹配整段自然语言。标准题判定意图、语义指标绑定、计划与工具选择、SQL 安全执行、结果值/单位/粒度；数值按案例声明的绝对或相对容差计算。所有对用户给出的数字必须能定位到同一运行的 Evidence 与通过的 Validation，且值与来源一致。安全案例判定真实执行是否被阻断，不能仅凭回答写了“无法操作”就算安全通过。语言清晰度、礼貌性与帮助性单独人工复核，模型辅助评分只能作为非门禁参考。

沿用项目原计划门槛：标准问题意图准确率和可信指标绑定准确率均 ≥95%，语义查询执行成功率 ≥99%，标准结果正确率 ≥95%，多轮上下文保持 ≥90%，恢复成功率 ≥99%；答案数字证据一致、未授权访问阻断、危险 SQL 阻断均为 100%。首次基准运行后固化用于 CI 的离线阈值；真实模型基准展示相同指标与置信说明，但不以一次波动直接阻断普通代码合并。任何单个严重安全失败直接标红，不能被平均分掩盖。未运行、被预算截断或基础设施错误不计为通过，也不能从分母中静默排除；界面分别显示“已评估通过率”和“全案例覆盖率”。

## 5. 权限、预算与可靠性

- 新增默认拒绝的评测读取与运行管理动作。系统管理员和工作空间管理员可在合成测试空间创建/取消真实模型基准；审计员可只读查看结果；其他角色无评测管理入口。所有 API 强制工作空间隔离。
- 创建运行前显示案例数、预计调用上限、token 上限和最长时长。服务端在每次调用前预留本次请求的最大允许输出 token，并结合输入 token 估算核对剩余额度，在网关返回后落库实际 usage；达到任一上限即停止后续案例。供应商实际计费 token 仍以返回值为准，不能将本地估算称为绝对成本上限。单次金额上限若没有可靠价格配置，不提供“金额已保证”的表述。批量付费运行需用户针对该次范围明确发起，不由 CI 或定时任务自动触发。
- 运行创建使用幂等键，事务内写入 Outbox；逐案例使用条件状态转换和尝试编号。Worker 崩溃后恢复未完成案例；已经确认计量的模型调用不得通过简单重投再调用，无法确认是否已到达供应商的调用标为 `usage_uncertain` 并暂停等待人工处理，避免重复计费。
- 每个案例状态为 `queued/running/passed/failed/blocked/infra_error`；运行状态为 `queued/running/completed/partial/failed/cancelled`。`blocked` 表示预算或安全前置条件阻止运行，不是测试成功。断言失败保留可定位的安全化失败原因；基础设施故障不伪装为 Agent 能力失败。
- 评测操作写入审计。结果 API 不暴露模型密钥、连接凭据、隐藏资源、完整用户数据或供应商原始请求；运行日志只记录关联 ID、阶段、耗时、用量和错误类别。

## 6. 产品交互

评测中心首页显示当前案例集版本与五类数量、最近一次离线/真实模型基准、各质量门槛、覆盖率和趋势。详情页按类别、断言、状态筛选案例，可从失败项跳转既有 Agent Run 技术详情及 Evidence；权限不足时只给最小披露提示。真实模型创建页明确列出数据快照、模型版本、预算与预计最多调用量，须二次确认；运行时显示进度、已消费额度、取消入口和中断原因。页面不得把离线模拟结果标成“DeepSeek 实测”，不得用没有真实运行记录的截图作为已完成证明。

## 7. 实施顺序与验收

1. 领域契约、案例集校验器和首批人工审阅案例；先使类别配额与纯确定性断言可在本地运行。
2. 离线执行适配现有 Agent 入口，扩展至 140 组；覆盖标准、多轮、歧义、异常和安全，形成机器可读 JSON 与人可读摘要。
3. 持久化、迁移、受权 API 与评测中心页面；验证跨空间隔离、幂等、失败恢复和版本对照。
4. 真实模型手动基准和预算闸门；先用少量案例验证用量、暂停和恢复，再由用户对完整付费批次单独授权。
5. 通过 Ruff、严格 MyPy、Pytest、ESLint、TypeScript、Vitest、Playwright、迁移往返与真实合成环境验收。记录各类别分母、失败详情、版本、成本及未通过项；达到门槛后才标记 M8-02/03 完成。

M8-04 可观测性随后接入 OpenTelemetry、Prometheus 和结构化日志，但评测中心的 `run_id/case_id` 将作为预留关联键。M8-01 沙箱最后单独设计，默认不给 Agent 任意 Python 执行权限；现有确定性分析工具继续优先使用。
