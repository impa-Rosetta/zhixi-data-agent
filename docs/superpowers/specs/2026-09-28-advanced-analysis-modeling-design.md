# 高级分析与建模引擎：三批交付规格

日期：2026-09-28。状态：用户已批准三批方向；本文待用户审阅，尚未开始实现。

## 1. 目标与范围

补齐 A07 官方文件技术要求中的相关分析、异常分析、简单建模代码、模型训练、评估、推理及结果解释，并融入现有持续会话。沿用 Python/FastAPI、PostgreSQL、Celery、React、工具注册表和 Plan–Execute–Verify，不迁移框架，不另造聊天系统。

三个连续交付批次：

1. 相关性与统计异常分析：真实工具、权限/证据链、散点图与异常图。
2. 六类机器学习建模：受控任务、隔离运行、版本化模型、训练/评估/推理/解释。
3. 持续对话整合：意图与工具选择、澄清、进度、结果卡片、代码查看、上下文追问、报告整合。

每批先完成底层能力及验收，再开放对话能力；工具存在于注册表但没有执行处理器时不得宣称可用。六种算法全部真实执行后才能宣称完成建模要求。任意用户 Python 上传执行不是本规格范围，原有通用脚本沙箱缺口不会因此自动关闭。

## 2. 现状与方案选择

当前 `packages/analysis_engine` 提供描述统计与受限 ChartSpec；`analysis.correlate`、`analysis.detect_anomaly` 仅注册规格。Agent 路由尚无相关性、异常、训练和推理任务。尚无持久化训练任务或模型版本。

选择受控工具 + 严格任务协议 + 隔离建模执行器。相比直接执行 LLM 生成的任意脚本，更容易验证权限、算法参数、资源和结果；相比外部 AutoML 平台，沿用现有部署且不向第三方传输明细。LLM 负责理解、字段选择、任务组织、自然语言解释，不负责凭空给出统计值、评估分数或执行不受控代码。

## 3. 共用数据与证据边界

工具输入引用当前空间内已校验的查询产物及不可变数据快照，不接受用户指定数据库连接、文件路径或 SQL/Python 字符串。读取前重新检查成员权限、来源状态、语义/目录版本、产物所属空间、证据关联和内容摘要；不以曾经有权限代替当前授权。

禁止把查询分页中的第一页当成完整训练集。模型数据准备使用专用只读查询，显式记录总行数、抽样方法、过滤条件、列说明与缺失分布。超过上限时澄清筛选或经用户选择确定性抽样，不能静默裁剪后宣称全量。

上限：20,000 行、50 个输入特征、20 MiB 编码输入；数值必须有限，布尔不自动当数值。模型摘要和脱敏样本可供 LLM 理解；密钥、数据库凭据、完整敏感明细不进入提示或日志。原始明细只在经授权的数据准备与隔离执行链路使用。

所有成功结果关联来源快照、查询产物、工具版本、规范参数、样本处理记录、计算输出及验证记录。关联失效时阻止继续推理，并用自然语言解释重新准备数据的方法。

## 4. 第一批：相关性与统计异常

### 4.1 相关性

新增严格的相关性请求/结果协议及真实处理器。输入为同一粒度下两个数值字段、方法（Pearson 或 Spearman）与来源产物。默认 Pearson；用户明确排名关系时采用 Spearman，不同时试很多方法后只挑最好看的一个。

按同一行配对、删除任一字段为空的配对，记录有效/丢弃样本数；少于 3 对、常量列、非有限值、不存在字段返回明确原因，不输出虚假系数。Spearman 使用平均秩处理并列值。输出系数、方法、字段、样本处理及“相关不代表因果”提示，不把短样本相关性包装成统计显著结论。

跨表分析必须先证明业务对象及时间粒度一致，使用目录/语义关系完成授权查询。不能把两个独立列表按位置拼接，也不能建立笛卡尔积。没有可信关系时在对话中询问关联对象或粒度。

### 4.2 统计异常

第一批实现确定性的 IQR 检测，不把它称为 Isolation Forest。协议记录检测字段、阈值倍数（默认 1.5，范围 1–3）、四分位数、上下界、异常行定位及样本处理。至少 8 个有效样本；四分位距为零不强行制造异常，返回无法以该方法可靠判断的说明。

结果使用已有受限图表接口展示；相关性为散点图，异常为按时间/类别排列的数值图并标记异常点。图表只引用真实计算结果，不能以文字生成图片代替数值图表。

## 5. 第二批：机器学习

### 5.1 算法与严格任务协议

新增 `ModelSpec`：算法、任务类型、输入字段、目标字段（监督任务必填）、来源快照、划分方式、时间/分组字段、随机种子、允许的超参数及解释要求。Pydantic 严格验证，拒绝未知参数/字段/路径/执行内容。

| 算法 | 任务 | 真实输出 |
| --- | --- | --- |
| 线性回归 | 数值回归 | MAE、RMSE、R²、系数、预测 |
| 决策树 | 分类或回归，类型明确 | 对应评估、树规则/特征重要性、预测 |
| 随机森林 | 分类或回归，类型明确 | 对应评估、特征重要性、预测 |
| 逻辑回归 | 分类 | 混淆矩阵、precision/recall/F1、系数、预测 |
| KMeans | 聚类 | 簇规模/中心、可计算时的 silhouette、新样本簇标签 |
| Isolation Forest | 异常检测 | 异常分数/标签/占比、新样本检测 |

不把上述表中的六类算法扩展成无边界插件执行平台。估计器及转换器均为代码内白名单；用户不能指定导入路径。

### 5.2 数据与评估正确性

监督任务至少 30 条有效样本；分类各类别至少 5 条，训练与验证均须包含必要类别。不满足条件说明问题并建议补数据，不伪造评估。聚类/异常至少 20 条有效样本。KMeans 的 K 默认 3，允许 2–10 且小于有效样本数；类别含义不能自动编造成业务标签。

先划分训练/验证数据，再仅在训练集拟合缺失填补、编码和标准化；统一使用 Pipeline/ColumnTransformer。默认留出 20%，固定随机种子 42。具有未来预测含义的任务按时间划分；有同设备/批次重复观测的任务按用户确认的分组划分，避免对象泄漏；不能仅按随机拆分宣称具有未来预测能力。

分类指标明确平均方法及类别，ROC-AUC 仅在标签/概率和验证类别符合条件时计算。R² 或 silhouette 无定义时显示不可计算原因而非 0。无人工异常标签时不声称异常准确率；系数、重要性、聚类与异常说明均提示其业务解释边界。

监督模型与简单基线比较，记录验证样本、真实值/预测值及误差摘要。自动建议算法不替用户推断未知预测目标；不增加无预算的搜索调参。

### 5.3 安全隔离与执行任务

新增专用建模执行包和任务服务，不在 API 请求进程训练，也不把 Docker socket 挂入 API 或通用 Worker。数据准备由现有授权链路完成，任务执行仅接收严格规格及已验证文件快照。

采用受信任的主机执行代理调度固定建模镜像：代理只接受已持久化任务 ID，从受限任务目录读取固定清单，镜像、启动参数、输入/输出路径由代理生成，用户不能提交 Docker 参数。代理不对公网开放，启动脚本管理其生命周期；没有代理时返回服务未配置，不降级到不隔离训练。

单任务容器：非 root、无网络、只读根文件系统、禁止权限提升、丢弃 capabilities、2 CPU、1 GiB 内存、128 PID、300 秒墙钟超时；输入只读挂载、输出限额 20 MiB、临时空间 128 MiB，不提供数据库、Redis、MinIO 凭据。代理位于容器外，负责超时/取消和清理，不要求无网络容器连接消息队列。

数据库任务状态为 queued/running/succeeded/failed/cancelled，记录 attempt、租约、幂等键和输入摘要。过期任务不能发布结果；取消后旧 attempt 的输出不可覆盖状态。输出先通过 schema、文件大小、路径和摘要校验，再事务性发布模型/证据。异常返回安全错误码及自然语言说明，不泄露主机路径或堆栈。

### 5.4 模型存储与推理

新增空间内模型及不可变版本，冻结规格、特征模式、来源、算法/依赖版本、评估和模型摘要。使用内部生成的 skops 模型格式，加载时仅允许实现中逐项列举的估计器/转换器类型；发现未知类型拒绝，不根据文件自报类型动态放行。禁止外部 pickle/joblib/模型文件上传执行。

模型文件由对象存储保存，持久化内容摘要；加载时校验空间、权限、版本、来源状态、摘要及兼容依赖版本。推理走同一隔离执行器；未知字段、缺少必需字段、类型变化在推理前报告，不重新训练来掩盖不兼容。

权限新增 model.read/train/predict：管理员、数据管理员、分析员可使用；审计员仅查看授权空间模型/评估，不训练或推理。撤权后的排队任务拒绝启动；运行中撤权禁止发布可访问产物，取消/删除不删除源业务数据。

## 6. 第三批：持续对话与可解释交付

扩展现有 Intent、RouteDecision、计划生成和续问上下文，不另建一套仅支持关键词的路由。新路由覆盖 correlation、anomaly_detection、model_training、model_prediction、model_explanation；ModelSpec 独立协议承载建模字段，避免塞入现有字符串过滤器。

LLM 输出严格协议，服务端检查可用工具、权限、参数和预算；非法输出最多一次受控修正后自然语言说明，不能改成介绍系统能力来掩盖分析失败。普通打招呼与现有查询能力保持兼容。

持续会话保存最近有效数据引用、模型版本与任务 ID。用户可在同一会话中依次问“分析相关性”“标出异常”“训练模型”“解释效果”“用这些数据预测”，但切换主题时清除不兼容模型上下文。缺目标、关联关系或特征时由 Agent 直接提问；确定性默认值公开说明，不要求用户逐项填写表单。

模型训练首次执行前展示来源、算法/目标、样本规模和资源上限，并复用现有确认机制；已经确认的相同规格幂等重投不再次确认，改变目标/数据则重新确认。分析低风险只读统计不添加额外确认。

保留底部对话框。任务中显示真实排队/数据准备/训练/校验进度及取消入口，不伪造百分比；完成显示结论、图表、评估、模型版本、证据和可继续追问的建议。故障、权限不足、数据不足均由 Agent 自然语言回应并给出可执行下一步。

SQL 和建模 Python 展示使用真实执行参数生成的受控模板，不展示一段与执行过程无关的“示例代码”。展示代码可审阅但不是绕过工具边界的任意执行入口。模型结果卡片适配桌面/移动端，并可纳入现有报告；报告解释有真实引用，不能由 LLM 编造模型表现。

## 7. 数据准备与交付验收

增加独立、固定种子的模拟明细数据集，至少 1,000 条，覆盖时间、产线/设备、停机量、生产量、检验量、不良量及明确生成的目标标签。标记模拟数据，保留生成规则、版本与故意设置的异常；不覆盖用户现有表或真实数据，不把模拟关系当作企业实证。

旧的月度少量数据只用于趋势，不能用于证明模型质量。模拟数据用于六算法端到端可重复演示；另用未参与拟合的样本检验推理。未知数据源的完整适配验收仍单独记录，不能由这个固定样例替代。

每批验收：

1. 数学/算法单测、严格输入边界、空值/常量/样本不足测试；同空间成功、跨空间和撤权拒绝；真实数据工具调用、产物/证据入库及真实图表可见。
2. 六算法实际训练和推理、数据划分/泄漏防护、模型保存/重新加载、坏摘要/未知类型拒绝；真实容器无网络、超时、取消、重复投递、陈旧 attempt 拒绝；真实 API/Worker/对象存储联合闭环。
3. 同一会话至少五轮实测，包含澄清、训练确认、进度、模型解释、推理、切换话题；真实浏览器桌面/移动图表和代码查看；真实报告引用；基础聊天/查询/趋势回归不退化。

离线测试不调用付费 LLM；真实 DeepSeek 验收需单独的调用预算授权，其准确率不能以离线桩结果代替。保持 Ruff、MyPy、前后端测试、构建、安全审计及覆盖率门槛；新增依赖锁定实际版本，API/Worker/建模镜像一致并绑定源码 revision。

## 8. 完成定义与文档同步

每批分别提交代码、测试、真实验收记录、状态更新和用户可复制的问题。仅提交本批修改，不夹带用户未提交文档。沿用已授权的 GitHub 推送流程；遇权限/网络阻碍如实报告，不声明已经推送。

三批完成不等于项目整体生产就绪：通用脚本沙箱、未知数据源完整适配、真实模型准确率评测、完整远端 CI、正式灾备/性能及最终比赛材料仍按各自验收关闭。报告中区分已实现、已验证和计划功能，效果图后续替换为真实页面截图。
