# M2 数据源接入与元数据发现设计

- 状态：待整体确认
- 日期：2026-09-05
- 上游规格：`docs/superpowers/specs/2026-09-04-a07-data-agent-design.md`
- 适用里程碑：M2

## 1. 目标

为智析 Data Agent 建立产品级企业数据接入底座。管理员能够安全接入未写死结构的 PostgreSQL 或 MySQL 数据库，验证连接与只读权限，异步扫描结构，按授权采集有限样例和基础画像，并浏览版本化元数据及结构变化。

M2完成后，后续语义模型、查询编译器和 Agent 工具只依赖平台标准目录，不直接理解不同数据库的系统表差异，也不直接持有企业数据库凭据。

## 2. 范围

### 2.1 本阶段交付

- PostgreSQL与MySQL数据源的创建、编辑、启用、停用和软删除；
- AES-256-GCM信封加密凭据，支持密钥版本和未来Vault/KMS替换；
- 连接测试、TLS状态和只读权限校验；
- Schema、表、视图、字段、主键、外键和索引扫描；
- 管理员授权后的限量样例与基础字段画像；
- 不可变扫描快照、当前发布版本和相邻版本结构差异；
- 首次自动扫描、手动刷新和默认关闭的定时扫描策略；
- 数据源列表、连接向导、详情、扫描进度、目录浏览和变化提示页面；
- 权限、审计、错误分类、指标和自动化测试。

### 2.2 不在本阶段

- 任意SQL编辑器或用户自定义SQL执行；
- Agent自然语言规划和业务查询；
- 自动语义映射、指标发布、跨源联邦查询和CDC；
- Oracle、SQL Server、ClickHouse、Excel或CSV连接器；
- 远程数据执行节点和外部数据目录平台集成。

## 3. 已确认决策

1. 同时交付PostgreSQL和MySQL，先完成PostgreSQL纵向闭环，再实现MySQL适配；
2. 元数据扫描自动执行，样例和画像必须由管理员显式授权；
3. 使用信封加密，首版由部署环境提供主密钥，接口预留Vault/KMS；
4. 首次连接自动扫描，支持手动刷新和可配置定时扫描；定时扫描默认关闭；
5. 新扫描生成差异，不自动覆盖后续已发布的语义映射；
6. 使用内置连接器和平台版本化目录，不采用FDW或外部数据目录作为核心依赖。

## 4. 总体架构

```text
Web 数据源管理
  → FastAPI / Policy Engine
  → DataSource Service
      → Secret Provider
      → Network Policy
      → Connector Registry
      → Scan Job Service
  → PostgreSQL 平数据与任务状态

Celery Worker
  → 领取连接测试或扫描任务
  → 临时解密凭据
  → PostgreSQL / MySQL只读连接
  → 标准化MetadataDocument
  → 原子发布Catalog Snapshot与Schema Diff
  → 清除明文、释放连接、记录审计与指标
```

API是控制面，不在请求线程中执行完整扫描。Worker是数据接入执行面。平台目录是后续模块唯一稳定依赖。

## 5. 模块边界

### 5.1 DataSource Service

负责生命周期、权限、状态转换、扫描调度和审计。它只依赖抽象Secret Provider、Network Policy、Connector Registry和任务队列，不包含数据库方言逻辑。

### 5.2 Secret Provider

提供`encrypt`、`decrypt`和`rewrap`能力。首版使用本地主密钥实现，密文信封包含算法、密钥版本、加密数据密钥、凭据密文、随机nonce和认证上下文版本。

### 5.3 Connector Registry

按`postgresql`或`mysql`解析连接器。连接器统一实现连接测试、服务器信息读取、只读权限检查、元数据扫描、受控采样和连接关闭。

PostgreSQL使用`psycopg`，MySQL使用MIT许可的`PyMySQL`。SQLAlchemy Inspector承担跨数据库基础反射，各连接器补充方言特有信息。

### 5.4 Metadata Scanner

将连接器输出规范化为与方言无关的`MetadataDocument`，校验大小和完整性后生成目录快照。扫描器不访问Web会话，也不决定用户权限。

### 5.5 Catalog Diff

比较同一数据源相邻成功快照，输出Schema、表、字段、约束和类型变化。差异是确定性计算结果，不由模型生成。

## 6. 数据模型

### 6.1 `data_sources`

- `id`、`workspace_id`；
- `name`、`description`、`source_type`；
- `host`、`port`、`database_name`；
- `tls_mode`、`network_policy_id`；
- `status`：`draft`、`testing`、`ready`、`degraded`、`disabled`、`deleted`；
- `health_code`、`last_checked_at`、`last_success_at`；
- `active_snapshot_id`；
- 乐观锁版本、创建人、更新人和时间戳。

主机、端口和数据库名称可见但属于敏感配置，只向有管理权限的成员返回。响应不包含用户名、密码或可复原连接串。

### 6.2 `data_source_secrets`

- `data_source_id`；
- `provider`、`key_version`、`algorithm`；
- 加密数据密钥、凭据密文、nonce及格式版本；
- 创建、轮换和销毁时间。

用户名、密码、TLS客户端证书和额外连接参数序列化后整体加密。删除数据源时销毁当前密文，历史目录不保存凭据副本。

### 6.3 `scan_jobs`

- `id`、`workspace_id`、`data_source_id`；
- `job_type`：`connection_test`或`metadata_scan`；
- `trigger`：`initial`、`manual`或`scheduled`；
- `status`：`queued`、`running`、`succeeded`、`failed`、`cancelled`；
- 幂等键、Celery任务ID、阶段、进度和尝试次数；
- 安全错误码、开始/结束时间和触发人。

同一数据源通过数据库约束和分布式锁保证最多一个活动扫描。任务投递采用事务内outbox记录，避免数据库提交成功但队列消息丢失。

### 6.4 `catalog_snapshots`

- `id`、`workspace_id`、`data_source_id`、递增版本；
- 数据库产品及版本、扫描选项、内容摘要；
- 对象数量、采样状态、开始/完成时间；
- `status`：`building`、`published`或`rejected`。

成功扫描在单个事务中发布快照并更新`active_snapshot_id`。构建失败不会污染当前目录。

### 6.5 目录实体

使用规范化表保存Schema、关系对象、字段、约束、索引、样例和画像，全部包含`workspace_id`、`data_source_id`与`snapshot_id`，确保空间隔离和版本查询。

样例值单独保存，可按快照整批删除。画像仅保存允许的聚合结果，不保存无法解释的二进制对象。

### 6.6 `scan_schedules`与`catalog_diffs`

扫描计划保存时区、每日或每周频率、下次执行时间和启停状态。差异记录保存前后快照、严重级别、变化类型和稳定对象标识。

## 7. 凭据与网络安全

### 7.1 信封加密

- 主密钥必须是部署时提供的32字节随机密钥，不写入仓库和数据库；
- 每个凭据版本生成独立随机数据密钥；
- 数据密钥和凭据分别使用AES-256-GCM加密；
- 工作空间ID、数据源ID和格式版本进入AAD，防止跨资源替换密文；
- 解密结果只存在于Worker局部生命周期，不进入任务参数、日志或异常；
- 支持新主密钥版本对数据密钥执行`rewrap`，无需暴露或重新提交数据库密码。

缺少或格式错误的主密钥时，应用拒绝启动相关能力；生产配置不得回退到默认密钥。

### 7.2 SSRF与网络策略

创建和测试连接前解析全部A/AAAA记录，并在连接时再次核对解析结果，降低DNS重绑定风险。默认拒绝：

- 环回、链路本地、组播、未指定地址；
- 云元数据地址；
- 未被策略明确允许的私有CIDR；
- 非数据库允许端口和包含协议/路径的主机输入。

私有化部署通过工作空间网络策略配置允许CIDR和端口。本地开发策略可显式允许Docker网络及`host.docker.internal`，但生产默认配置不自动继承。

### 7.3 只读保证

- 接入文档要求使用独立最小权限账户；
- 连接测试读取数据库权限与会话只读状态；
- 扫描和采样事务显式设置为只读，并配置连接、锁和语句超时；
- M2不暴露任何DML/DDL执行入口；
- 无法证明只读时返回可行动错误，数据源不得进入`ready`。

## 8. 扫描与采样

### 8.1 扫描范围

管理员选择允许扫描的Schema。系统Schema默认排除。扫描读取表、视图、字段类型、可空性、默认值、注释、主键、外键和索引。

对象使用稳定键`source/schema/object/column`匹配版本。标识符保留数据库原始大小写，同时保存规范化检索值。

### 8.2 安全采样

采样默认关闭。开启时可配置Schema/表白名单，每表最多20行、每字段最多20个非空样例、单值最长256字符、单次任务总样例字节上限和查询超时。

系统先按名称、类型和统计特征识别潜在敏感字段。命中邮箱、电话、身份证、银行卡、密钥、密码等类别时，只保存类型标签、空值率、基数等非原值画像；文本样例执行遮罩。二进制、大对象、JSON超长内容和未知复杂类型不保存原值。

基础画像包括行数估计、空值率、近似基数、数值范围和有限长度统计。不得为精确画像对业务表执行无界全表扫描。

### 8.3 一致性与资源限制

每个连接器使用小连接池或单任务短连接，默认最大并发2、连接超时5秒、语句超时10秒、扫描任务总时限10分钟。目录构建使用平台数据库事务，与企业数据库不要求分布式事务。

## 9. 生命周期与状态机

```text
draft → testing → ready
           ↓        ↓
         degraded ←─

ready/degraded → disabled → testing
任意非deleted状态 → deleted
```

- 新建数据源先保存加密配置，再自动投递连接测试；
- 测试成功且只读校验通过后进入`ready`并自动投递首次扫描；
- 网络或凭据失败进入`degraded`，不删除上一成功快照；
- 编辑连接配置需要乐观锁，保存后重新测试；
- 停用会阻止新任务并撤销排队任务；
- 软删除立即销毁凭据、停用计划并阻止访问，目录按保留策略等待管理员清理。

## 10. API契约

所有端点位于`/api/v1/workspaces/{workspace_id}`并复用Policy Engine。

- `POST /data-sources`：创建配置和加密凭据；
- `GET /data-sources`：分页、筛选和健康摘要；
- `GET /data-sources/{id}`：脱敏详情；
- `PATCH /data-sources/{id}`：乐观锁更新，密码留空表示不轮换；
- `POST /data-sources/{id}/test`：幂等投递连接测试；
- `POST /data-sources/{id}/scans`：幂等投递扫描；
- `GET /data-sources/{id}/jobs`与`GET /scan-jobs/{job_id}`：任务状态；
- `GET /data-sources/{id}/catalog`：当前或指定快照目录；
- `GET /data-sources/{id}/diffs`：结构变化；
- `PUT /data-sources/{id}/schedule`：设置或停用计划；
- `POST /data-sources/{id}/disable`、`POST /enable`、`DELETE /data-sources/{id}`。

耗时操作返回`202 Accepted`和任务资源。前端轮询使用退避与页面可见性控制；后续可无损替换为SSE。

## 11. 前端体验

在现有企业侧栏开放“数据源”导航：

1. 数据源列表展示类型、状态、最近成功、当前快照和结构变化数量；
2. 分步向导收集基础信息、网络/TLS、凭据、扫描范围和采样授权；
3. 保存后显示连接测试与首次扫描的真实阶段进度；
4. 详情页分为概览、结构目录、变化、任务和设置；
5. 目录树支持Schema、表和字段浏览，字段详情展示类型、注释、约束和脱敏画像；
6. 错误信息给出修复动作，但不显示底层连接串或堆栈；
7. 无管理员权限的用户只能查看已授权目录，不显示连接配置和凭据操作。

页面不伪造扫描结果。空状态明确引导创建数据源，失败状态保留最近成功目录。

## 12. 错误模型与恢复

稳定错误码至少包含：配置无效、网络策略拒绝、DNS变化、连接超时、TLS失败、认证失败、只读校验失败、权限不足、方言不支持、扫描超限、任务重复、任务取消和内部错误。

瞬时网络错误按指数退避最多重试2次；认证、权限、网络策略和配置错误不自动重试。所有任务步骤可重复执行，只有完整快照能够发布。

服务重启后，超时的`running`任务由回收器标记失败或安全重投。前端刷新后通过任务资源恢复进度。

## 13. 审计、日志与指标

审计事件覆盖创建、配置更新、凭据轮换、连接测试、扫描、采样授权、计划变更、启停和删除。事件只保存资源ID、动作、结果和安全错误码。

结构化日志包含请求ID、任务ID、工作空间ID、数据源ID、连接器、阶段和耗时；统一脱敏器移除凭据字段与数据库错误中的连接信息。

核心指标包括连接测试成功率、扫描成功率与耗时、对象数量、采样字节数、队列等待时间、结构变化数量和按错误码统计的失败数。

## 14. 测试策略

### 14.1 单元测试

- 加密往返、AAD替换拒绝、密钥轮换和错误密钥；
- 网络地址分类、DNS重绑定检查和CIDR策略；
- 状态机、幂等键、目录规范化、差异算法和脱敏器；
- PostgreSQL/MySQL方言到标准目录的映射。

### 14.2 API与策略测试

- 管理员与普通成员权限；
- 跨工作空间拒绝；
- 响应不泄漏凭据；
- 乐观锁冲突、重复扫描、停用和软删除；
- 任务和目录分页筛选。

### 14.3 集成测试

Docker Compose增加专用PostgreSQL与MySQL样例数据源。测试正确凭据、错误凭据、超时、TLS/权限不足、首次扫描、重复扫描、结构变化和采样上限。

### 14.4 前端测试

覆盖创建向导校验、状态轮询、失败恢复、目录浏览、采样确认、角色限制和移动端布局。

## 15. 验收标准

1. 管理员可以从Web创建PostgreSQL和MySQL数据源，并看到真实连接测试结果；
2. 非只读账户或网络策略外地址无法进入`ready`；
3. 首次扫描生成可浏览目录，包含表、字段、主外键和索引；
4. 开启采样后只产生受限、脱敏结果，关闭时不读取或保存样例；
5. 数据库结构变化后新扫描生成准确差异，旧快照仍可追溯；
6. 同一数据源重复扫描受控，Worker重启不会发布残缺快照；
7. API、日志、任务载荷和审计事件不包含明文凭据；
8. PostgreSQL/MySQL真实容器集成测试、后端质量门禁、前端测试和生产构建通过；
9. 全栈Docker Compose健康，桌面和窄屏关键流程通过浏览器验收；
10. 技术决策、运行手册、验收记录和项目日志更新并推送GitHub。
