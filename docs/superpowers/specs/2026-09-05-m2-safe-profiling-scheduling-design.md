# M2 安全采样、字段画像与定时刷新设计

- 状态：已批准，待实施
- 日期：2026-09-05
- 所属阶段：M2 数据源接入与元数据发现
- 对应切片：切片五
- 前置能力：M2 切片一至四

## 1. 目标与边界

本切片在已发布、不可变的数据库目录快照上补充语义建模所需的有限数据特征，并建立可恢复的定时刷新链路。系统必须在管理员明确授权、表级白名单和硬资源预算内运行，默认不读取或保存任何业务样例。

本切片交付：

- PostgreSQL 与 MySQL 一致的安全采样及字段画像契约；
- 数据源级采样策略、每日或每周扫描计划；
- 与目录快照绑定的画像、脱敏样例和画像状态；
- 画像任务的幂等投递、协作式取消、心跳、超时回收和受控重试；
- 管理策略、计划、任务和画像结果的后端 API；
- 双数据库真实链路、迁移回滚和自动化质量门禁。

本切片不交付数据源管理前端、任意 SQL 执行、全表精确画像、跨表推断、语义模型生成或 Agent 工具。前端统一留到 M2 切片六。

## 2. 核心决策

### 2.1 元数据与画像采用两阶段任务

元数据扫描成功后先发布目录快照，再检查该数据源的采样策略。若策略已启用且当前快照命中白名单，则创建独立的 `profile_scan` 任务并通过事务 Outbox 投递。

这样可以保证：

- 画像失败不阻塞新的元数据目录发布；
- 画像可以针对同一快照独立取消和幂等重试；
- 快照明确展示画像状态，不会把部分结果冒充成功结果；
- 元数据扫描和画像任务各自拥有可理解的超时、错误和审计边界。

### 2.2 样例持久化默认关闭

只有工作空间管理员或数据管理员明确启用策略后，系统才可以读取白名单表。非敏感字段允许保存有限、截断且脱敏的样例；敏感字段永远不保存原值。关闭采样不会创建画像任务，也不会连接业务表读取数据。

### 2.3 统计结果不冒充精确全表统计

数据库目录统计提供的行数标记为 `estimated`，从有限样例计算的结果标记为 `sampled`。本切片不得为了精确空值率、基数或范围执行无界全表聚合。

## 3. 领域模型

### 3.1 `sampling_policies`

每个数据源最多一条策略：

- `workspace_id`、`data_source_id`；
- `enabled`，默认 `false`；
- `schema_allowlist` 和 `table_allowlist`；
- `max_rows_per_table`，范围 1 至 20，默认 20；
- `max_values_per_column`，范围 1 至 20，默认 20；
- `max_value_chars`，范围 16 至 256，默认 256；
- `max_bytes_per_table` 和 `max_bytes_per_job`；
- `statement_timeout_seconds`，范围 1 至 10，默认 10；
- `version`、更新人和时间。

表白名单使用稳定的 `schema/relation` 标识。空白名单表示不允许任何表，不解释为全部表。策略启用时必须至少选择一张普通表；视图默认不采样，避免触发不可控的复杂查询。

### 3.2 `scan_schedules`

每个数据源最多一条计划：

- `frequency`：`daily` 或 `weekly`；
- IANA `timezone`；
- 本地执行时间；
- 周计划的星期；
- `enabled`，默认 `false`；
- `next_run_at`、`last_enqueued_at`；
- `version`、更新人和时间。

所有计算后的触发时刻使用 UTC 保存。夏令时跳变时，同一个本地计划槽最多执行一次；不存在的本地时刻顺延到该时区下一个有效时刻。

### 3.3 任务扩展

`ScanJobType` 增加 `profile_scan`。`scan_jobs` 增加：

- `parent_job_id`：画像任务关联产生快照的元数据任务；
- `heartbeat_at`：Worker 最近一次存活确认；
- `cancel_requested_at`：协作式取消请求；
- `retry_of_job_id`：显式重试来源。

画像任务的 `snapshot_id` 必填。参数只保存非敏感的策略版本与预算快照，不保存数据库凭据。现有“同一数据源最多一个活动任务”约束继续覆盖元数据和画像任务。

### 3.4 快照画像状态

`catalog_snapshots` 增加：

- `profiling_status`：`disabled`、`pending`、`running`、`succeeded`、`failed`、`cancelled`；
- `profiling_error_code`；
- `profiling_started_at`、`profiling_finished_at`；
- `profiling_options`：本次执行使用的非敏感预算与策略版本；
- `profile_counts`：画像字段数、保存样例数和样例字节数。

元数据快照发布后不再修改目录实体；只允许更新该快照的画像状态和写入其附属画像记录。

### 3.5 `catalog_column_profiles` 与 `catalog_samples`

每个快照字段最多一条画像，包含：

- 样本行数、非空样本数、估算行数；
- 样本空值率、样本近似基数；
- 数值或日期的样本最小值、最大值；
- 文本样本最小、最大和平均长度；
- `sensitivity_type`、置信度与识别依据；
- 每个指标的来源 `estimated` 或 `sampled`。

样例表独立保存字段引用、顺序、脱敏字符串、原始类型标签和 UTF-8 字节数。它不保存原值哈希，避免低基数敏感值被离线枚举。样例可按快照整批删除，而不影响聚合画像。

## 4. 执行架构与数据流

```text
手动请求或计划到期
  -> 创建 metadata_scan 任务与 Outbox 事件
  -> Worker 发布不可变目录快照
  -> 读取启用的采样策略并冻结预算
  -> 创建绑定 snapshot_id 的 profile_scan 任务与 Outbox 事件
  -> Connector 在只读事务中逐表执行受限查询
  -> 进程内识别敏感字段、脱敏并累计预算
  -> 单事务替换该快照的画像与样例
  -> 更新快照画像状态和审计事件
```

画像任务开始前重新验证数据源仍处于 `ready`、策略仍启用、快照仍属于同一工作空间与数据源。任务使用冻结的预算确保执行语义可复现；管理员关闭策略会请求取消尚未开始或正在运行的画像任务。

目录扫描在发布快照的同一事务中创建画像任务，避免快照已发布但后续任务永久丢失。画像结果先在 Worker 内构建为有界文档，再在平台数据库单事务落库；失败时不保留部分画像。

## 5. 连接器契约

连接器协议增加 `profile_snapshot` 能力，输入为：

- 已授权的连接目标和临时解密凭据；
- 当前目录快照的关系与字段描述；
- 规范化表白名单；
- 不可突破的采样预算；
- 网络策略。

输出为方言无关的 `ProfileDocument`。PostgreSQL 与 MySQL 分别负责：

- 安全引用 Schema、表和字段标识符；
- 读取数据库提供的行数估计；
- 使用常量化 `LIMIT` 执行有限行查询；
- 配置连接、锁和语句超时；
- 启动显式只读事务；
- 在每次连接前后执行现有 DNS/IP 策略复核。

白名单只能从已发布目录对象解析为标识符，API 输入不能直接拼入 SQL。每张表只执行固定形态的查询。二进制、大对象、超长 JSON、空间类型和未知复杂类型不进入选择列。

## 6. 敏感识别与脱敏

识别分为三层：

1. 字段名称规则：邮箱、电话、身份证、银行卡、密码、密钥、令牌等中英文别名；
2. 数据类型规则：二进制、大对象和不可安全字符串化的类型直接禁止样例；
3. 有限值验证：结构化格式校验、校验位算法和高置信度正则。

字段只要被任一禁止规则命中，或者值验证达到高置信度，就丢弃该字段在内存中的全部样例，只保存敏感类型、置信度、识别依据和允许的聚合统计。日志、异常、审计和任务参数不得包含被读取的值。

非敏感文本仍经过通用遮罩器，以替换偶然出现的邮箱、电话、令牌和长数字串。随后按 Unicode 字符截断到配置上限，并按 UTF-8 字节计入表级和任务级预算。预算耗尽时停止读取后续值或表，并将结果标记为 `budget_exhausted`，不将其视为任务失败。

## 7. 调度、取消与恢复

Celery Beat 每分钟触发计划领取器。领取器在平台数据库事务中锁定到期计划，使用 `schedule:{schedule_id}:{scheduled_for}` 作为幂等键创建元数据任务与 Outbox 事件，并在同一事务中推进 `next_run_at`。并发领取者和重复投递不能为同一计划槽创建第二个任务。

取消采用协作式模型：API 设置 `cancel_requested_at`；Worker 在连接前、每张表前后和持久化前检查取消标记。取消后画像状态变为 `cancelled`，构建中的临时结果不落库。对底层驱动执行中的单条查询，依靠不超过 10 秒的语句超时形成取消上界，不使用不可靠的跨进程强制终止作为正确性基础。

Worker 在阶段转换和每张表完成后更新 `heartbeat_at`。回收器周期查找超过任务总时限且心跳过期的活动任务：

- 瞬时连接、网络或超时错误且尝试次数未超过 2 次时，创建带关联关系的新任务；
- 权限、策略、凭据、白名单和数据类型错误不重试；
- 超过重试上限后标记失败；
- 对应快照画像状态同步更新，元数据目录仍保持已发布。

所有 Worker 操作先检查任务终态，保证 Celery 至少一次投递不会重复写入结果。

## 8. API 与权限

新增端点：

- `GET/PUT /data-sources/{id}/sampling-policy`；
- `GET/PUT /data-sources/{id}/schedule`；
- `POST /data-sources/{id}/jobs/{job_id}/cancel`；
- `POST /data-sources/{id}/jobs/{job_id}/retry`；
- `GET /data-sources/{id}/catalog/snapshots/{snapshot_id}/profiles`；
- `GET /data-sources/{id}/catalog/snapshots/{snapshot_id}/profiles/{column_id}`。

只有工作空间管理员和数据管理员可以修改策略、计划、取消或重试任务。分析师和审计员只能读取策略摘要、任务状态和已授权画像；API 响应不返回任何被判定为敏感的原值。

策略启停、白名单与预算变更、计划变更、取消、重试、画像成功或失败均写入审计事件。审计详情只包含资源 ID、计数、状态与稳定错误码。

## 9. 稳定错误码

新增错误类别：

- `sampling.disabled`；
- `sampling.scope_empty`、`sampling.scope_invalid`；
- `sampling.budget_invalid`；
- `sampling.query_timeout`；
- `sampling.cancelled`；
- `sampling.profile_failed`；
- `schedule.invalid_timezone`、`schedule.invalid_expression`；
- `job.not_cancellable`、`job.not_retryable`；
- `job.stale_recovered`、`job.retry_exhausted`。

外部数据库驱动消息仍映射为稳定错误码，不直接进入 API、日志或审计。敏感识别器失败时采取失败关闭策略：该字段不保存样例，但其他字段可以继续画像。

## 10. 可观测性

结构化指标至少覆盖：

- 画像任务成功率、失败率、取消率和时长；
- 每次画像的表数、字段数、样例数和样例字节数；
- 因敏感、类型或预算被跳过的字段数；
- 计划延迟、重复计划槽抑制次数；
- 回收任务数、重试次数和重试耗尽次数；
- 按稳定错误码聚合的失败数。

指标和日志禁止使用 Schema、表、字段或样例值作为高基数标签；资源定位使用内部 ID。

## 11. 测试与验收

### 11.1 单元与契约测试

- 策略默认关闭、白名单解析和所有预算边界；
- 字段名称、类型、值规则、校验位与通用遮罩；
- UTF-8 截断和跨表总字节预算；
- PostgreSQL/MySQL 输出相同画像契约；
- 安全标识符引用与无任意 SQL 输入；
- 时区、夏令时、每日和每周下次执行时间；
- 任务幂等、取消、回收、错误分类和两次重试上限；
- 工作空间隔离、角色权限及敏感响应检查。

### 11.2 真实集成验收

在 Compose 中对 PostgreSQL 与 MySQL 样例源分别验证：

1. 采样关闭时只发布目录且零业务样例查询、零样例落库；
2. 启用策略后只访问白名单普通表；
3. 每表、每字段、单值和总字节预算均不可突破；
4. 邮箱、电话、身份证、银行卡、密码和令牌原值零落库；
5. 查询超时、取消和 Worker 重启不产生部分画像；
6. 同一计划槽重复领取只生成一个元数据任务；
7. 瞬时失败受控重试，永久失败不重试；
8. 两个目录版本的画像互不覆盖；
9. 迁移可升级、可回滚、可再次升级；
10. Ruff、格式检查、严格 MyPy、后端测试、前端检查和生产构建全部通过。

## 12. 完成定义

管理员能够为 PostgreSQL 或 MySQL 数据源明确授权有限采样并配置每日或每周刷新；系统只对快照中允许的普通表执行有界只读查询，敏感原值不会进入持久化、任务、日志或审计；画像结果带有明确统计语义并绑定不可变快照；调度、重复消息、取消、超时和 Worker 故障均可得到幂等、可追溯的处理。
