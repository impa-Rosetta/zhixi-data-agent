# M5 Agent 核心闭环设计规格

- 状态：已确认，待实施
- 日期：2026-09-07
- 上位规格：`docs/superpowers/specs/2026-09-06-a07-remaining-product-delivery-design.md`
- 范围：Model Gateway、运行状态、意图与语义绑定、Planner、Tool Registry、执行图和多轮上下文

## 1. 目标与边界

M5 将 M2 至 M4 已完成的数据治理、语义模型和安全查询能力组装为可恢复、可审计、受预算约束的 Agent 后端闭环。用户提交自然语言问题后，系统创建持久化运行，解析意图并冻结已发布语义版本，生成声明式计划，通过注册工具执行真实查询，验证证据并保存可供 M6 工作台消费的结构化结果。

M5 不交付正式对话界面、SSE、统计分析、图表或报告成品；这些属于 M6/M7。M5 会提供稳定的运行 API、状态和事件数据，使后续界面无需改写 Agent 内核。

完成 M5 不以模型能回答问题为标准，而以下安全不变量必须同时成立：

1. 模型不能直接访问数据库或持有数据库凭据；
2. 模型不能修改已发布指标口径、物理映射或权限策略；
3. 所有查询均经过 M4 编译、验证和验证 ID 执行链；
4. 低置信度或关键歧义必须暂停并请求澄清；
5. 重复消息、任务重试和服务重启不得重复关键副作用；
6. 最终状态必须引用工具结果和不可变证据，不能由模型伪造数字。

## 2. 方案选择

采用“确定性执行图 + DeepSeek 受控决策”的混合架构。LangGraph 负责节点编排、分支与检查点语义；领域状态、计划、预算、工具调用和证据由本项目自己的严格类型与数据库模型控制。模型只参与意图候选、语义候选、计划草案和文字组织，本地规则负责最终绑定、授权、安全和状态迁移。

不采用模型自由工具循环，因为其退出条件、权限和重试难以形成产品级保证；不采用完全自研图运行时，因为恢复、检查点和分支维护成本高且没有业务收益。

## 3. 模块结构

### 3.1 Model Gateway

`packages/model_gateway` 暴露供应商无关协议，业务代码不得导入 DeepSeek 或 OpenAI SDK。首个适配器使用 `httpx` 调用 DeepSeek 官方 OpenAI-compatible Chat Completions 接口，并支持：

- 普通与思考模式；
- JSON 结构化输出和工具调用；
- 流式增量的统一事件类型；
- 请求超时、有限指数退避和可重试错误映射；
- token 用量、延迟、模型和请求关联 ID；
- 可复现 Fake Gateway，用于默认测试和离线开发。

Base URL、模型 ID、超时和预算全部配置化。API Key 只从 `DEEPSEEK_API_KEY` 或部署 Secret 读取，不写入数据库、日志、Trace、前端状态、测试快照或 Git。思考内容只允许存在于受保护的活动检查点，并按保留策略清理。

### 3.2 Agent Core

`packages/agent_core` 定义运行状态、意图、绑定、计划、步骤依赖、上下文补丁、预算和退出原因。所有跨模块输入输出使用 Pydantic 模型，不传递自由字典作为长期契约。

执行图节点固定为：

```text
understand -> bind -> plan -> policy_check
  -> clarify | confirm | execute
  -> verify -> replan_once | present
  -> completed | failed | cancelled
```

每个节点进入前检查取消和预算，完成后原子保存状态与检查点。SQL 修正最多两次，整图重新规划最多一次；权限、安全和预算错误不可通过重规划绕过。

### 3.3 Tool Registry

`packages/toolkit` 以版本化定义注册工具，定义包含名称、描述、输入输出 JSON Schema、所需角色、风险级别、支持方言、超时、重试、幂等、缓存和证据类型。

M5 注册规格中的十二类工具，并真正接通核心闭环所需的：

- `catalog.search`；
- `semantic.resolve`；
- `query.metric`；
- `query.explore`；
- `run.request_confirmation`。

分析、图表和报告类工具在 M5 提供稳定定义及明确的不可用响应，M7 接入实现后不改变 Planner 契约。工具实现复用现有 Policy Engine、语义服务和 M4 查询内核，不复制权限或 SQL 安全逻辑。

## 4. 持久化模型

新增迁移建立以下工作空间隔离实体：

- `analysis_runs`：运行状态、当前节点、冻结版本、预算、幂等键和生命周期；
- `analysis_messages`：用户、助手和系统消息，保存结构化上下文补丁；
- `analysis_plans` 与 `analysis_steps`：不可变计划版本、步骤依赖和执行状态；
- `analysis_tool_calls`：工具版本、规范化参数摘要、幂等键、结果引用和错误分类；
- `analysis_artifacts` 与 `analysis_evidence`：结果摘要、校验和、来源版本及对象引用；
- `analysis_validations`：结构、数据和语义验证结果；
- `analysis_checkpoints`：可恢复状态、节点版本和乐观锁版本；
- `analysis_events`：单调序号事件，为 M6 断线续传提供数据基础。

同一工作空间和客户端幂等键只能创建一个运行；同一运行和消息幂等键只能追加一次消息；工具调用幂等键由运行、计划版本、步骤和规范化输入共同生成。

运行创建时冻结目录快照、语义模型版本、指标版本和工具定义版本。后续发布不会改变在途或历史运行的含义。

## 5. 意图、绑定与计划

意图协议包含领域、任务类型、指标、维度、筛选、时间范围、比较方式、期望输出、歧义项和置信度。模型输出先经过本地 Schema 校验，再由确定性绑定器与已授权目录及已发布语义版本核对。

出现以下任一情况时进入 `waiting_for_clarification`：置信度低于阈值、多个同分指标候选、缺失必要时间范围或用户术语无法唯一映射。澄清回复以结构化上下文补丁合并，不直接重写历史消息。

Planner 只能生成声明式步骤：工具名、工具版本约束、结构化参数、依赖、预期证据和完成条件。计划禁止内嵌 Python、Shell、任意 SQL、指标公式或数据库连接信息。探索 SQL 只能作为 `query.explore` 的受控草案进入 M4 完整安全流程。

## 6. API 与运行流程

M5 提供工作空间隔离的 REST API：

- 创建运行并提交首条消息；
- 获取运行、计划、步骤、预算、证据和事件；
- 追加澄清消息；
- 确认或拒绝待确认计划；
- 取消运行；
- 对允许恢复的失败运行发起幂等重试；
- 从最近有效检查点恢复运行。

API 请求只负责持久化命令并触发执行，耗时节点通过现有 Worker 执行。状态更新与 Outbox 同一事务提交，避免“状态成功但任务未投递”。M6 将直接复用 `analysis_events` 增加 SSE，不改变 M5 状态机。

## 7. 多轮上下文

上下文保存目标、已绑定指标、维度、筛选、时间、比较对象、数据集和 Artifact/Evidence 引用，不把大查询结果或完整历史反复发送给模型。

“只看 A 线”生成筛选补丁；“再和上月比较”保留目标和指标并增加时间比较；“换成不良率”替换指标后重新绑定。任何补丁都重新执行授权、可行性和预算检查。

## 8. 错误、安全与预算

错误分为澄清、语义不可用、权限拒绝、查询安全、数据质量、模型暂态、模型永久、工具暂态、预算耗尽、取消和平台内部错误。模型限流和网络瞬断可在幂等边界内重试；权限、安全及预算错误立即终止；已完成的查询、证据和产物不会因后续模型或呈现失败而丢失。

预算同时限制模型调用次数、输入输出 token、工具调用数、查询数、查询行数、运行时长、重规划次数和预计费用。超限在发起外部调用前失败关闭。日志只记录脱敏参数摘要、关联 ID、错误码和用量，不记录密钥、凭据、敏感原值或完整思考内容。

## 9. 测试与验收

自动化测试包括：

- Gateway 协议、结构化输出、工具调用、流式事件、超时、重试、错误映射和用量；
- 状态迁移、乐观锁、幂等、取消、预算和检查点恢复；
- 低置信度澄清、多候选绑定、不可行指标和跨空间越权；
- Planner 拒绝自由代码、任意 SQL、未注册工具和指标口径改写；
- Tool Registry Schema、权限、版本、风险和证据契约；
- PostgreSQL 与 MySQL 的真实目录、语义查询、验证 ID 执行和证据闭环；
- Worker 中断后从检查点恢复，重复投递不重复执行关键步骤；
- 秘密扫描、迁移往返、Ruff、MyPy、Pytest 和现有前端回归。

真实 DeepSeek 验收通过显式脚本启用并设置调用与 token 上限，默认 CI 使用 Fake Gateway。模型不可用时运行进入可恢复失败状态，不使用固定答案或模拟数据冒充成功。

## 10. 完成定义

M5 只有在迁移、Gateway、运行状态、绑定、Planner、Registry、执行图、多轮上下文、REST API、Worker、自动化测试、双数据库真实链路、可选真实 DeepSeek 验收、Compose 部署、验收记录、项目状态和技术决策文档全部一致后才标记完成。提交只包含 M5 文件，用户已有未提交内容不纳入提交，并在质量门禁通过后推送 GitHub。
