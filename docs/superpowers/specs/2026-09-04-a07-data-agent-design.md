# A07 企业数据底座智能问析 Agent 产品设计规格

- 状态：已确认
- 日期：2026-09-04
- 赛题：A07 企业数据底座智能问析 Agent 系统
- 首发领域：制造业质量分析

## 1. 产品目标

建设一套可私有化部署的企业数据智能分析平台，使不具备 SQL、脚本和数据建模能力的业务人员能够通过自然语言完成数据查询、指标分析、趋势与异常分析、可视化展示和报告生成。

产品不是自由对话机器人，也不是写死数据和问题的演示程序。核心能力是由结构化分析计划驱动，通过受控工具执行真实数据分析，并为结论提供可追溯证据。

## 2. 官方要求覆盖

| 官方关注点 | 产品能力 |
|---|---|
| 业务知识组织 | 业务对象、术语、规则、分析主题和版本化指标中心 |
| 数据资源理解 | 数据源连接、元数据扫描、字段采样、关系发现和语义映射 |
| 自然语言分析 | 查询、分组、排行、趋势、对比、异常、相关性和报告任务 |
| SQL/脚本执行 | 语义查询编译、受控 SQL 生成、只读执行和隔离分析工具 |
| 建模能力 | 异常检测、相关性及可扩展的机器学习工具接口 |
| 结果展示 | 表格、指标卡、图表、自然语言结论和报告导出 |
| Agent 闭环 | Plan–Execute–Verify 状态机、工具路由、受控重试和恢复 |
| 工程可用性 | 权限、安全、审计、评测、可观测性和容器化部署 |

## 3. 产品范围

### 3.1 第一阶段包含

- 工作空间、成员和角色管理；
- PostgreSQL、MySQL 数据源接入；
- 元数据扫描、样例与统计特征采集；
- 企业物理字段到平台语义概念的映射；
- 质量领域业务对象与 15–20 个可信指标；
- 自然语言问析及多轮追问；
- 分析计划、能力路由和受控工具调用；
- 语义查询编译及探索性 SQL；
- SQL AST 安全检查、只读执行、超时和结果限制；
- 趋势、对比、排行、相关性和异常检测；
- 表格、ECharts 图表、结论和证据链；
- 分析报告导出；
- Agent 执行追踪、审计及离线评测；
- Docker Compose 私有化部署和公网演示部署。

### 3.2 第一阶段不包含

- 修改企业生产数据库；
- 完整 BI 拖拽设计器；
- 手机原生应用；
- 实时流处理平台；
- 自主训练大型语言模型；
- 无限制 Python 代码执行；
- 生产、设备和库存领域的完整业务模板；
- 多 Agent 自由讨论式架构；
- 第一阶段 Kubernetes 强依赖。

## 4. 用户与权限

系统角色包括系统管理员、工作空间管理员、数据管理员、分析用户和审计员。

权限校验覆盖工作空间、数据源、Schema、表、字段、行级范围、工具能力和导出操作。权限由服务端 Policy Engine 强制执行，不能依赖模型遵循提示词。业务数据库统一使用只读账户。

## 5. 总体架构

采用 Monorepo 管理，逻辑上分为：

```text
Web 前端
  → API 服务
      → Agent Core
      → Semantic Model
      → Query Engine
      → Analysis Engine
      → Model Gateway
      → Policy Engine
  → Worker
  → Sandbox
  → PostgreSQL / Redis / S3
  → 企业只读数据源
```

代码计划按以下边界组织：

```text
apps/web
apps/api
apps/worker
apps/sandbox
packages/agent-core
packages/toolkit
packages/semantic-model
packages/query-engine
packages/analysis-engine
packages/model-gateway
packages/shared-contracts
```

第一阶段采用模块化单体加独立 Worker、Sandbox，避免过早微服务化。模块接口保持清晰，以便后续按负载和安全边界拆分。

## 6. Agent 架构

### 6.1 运行模型

采用受控 Plan–Execute–Verify 工作流：

```text
接收问题
→ 解析上下文和意图
→ 绑定业务语义
→ 生成声明式分析计划
→ 风险和权限检查
→ 选择能力及工具实现
→ 执行查询或分析
→ 验证结果
→ 必要时澄清、修正或重新规划
→ 生成可溯源结论
```

一次用户请求对应一个持久化 `AnalysisRun`。每个节点完成后保存检查点，支持服务重启后的恢复和重放。

### 6.2 模型职责

模型负责：

- 语言和业务意图理解；
- 歧义识别；
- 结构化分析规划；
- 非模板场景的 SQL 草案；
- 工具结果解释；
- 报告叙述生成。

确定性代码负责：

- 权限和安全策略；
- 指标公式及版本；
- 常见语义查询编译；
- 工具选择约束；
- SQL AST 校验和执行；
- 统计计算；
- 数值和证据一致性验证；
- 执行预算及退出条件。

### 6.3 工具路由

Planner 使用抽象能力名，例如 `query.metric_timeseries`。运行时结合数据库方言、工具版本、权限和策略选择具体实现。模型不会直接获得数据库凭证或自由执行权。

工具按五类组织：

1. 语义和元数据工具；
2. 查询工具；
3. 数据分析工具；
4. 可视化工具；
5. 输出与治理工具。

每个工具必须声明版本、输入输出 Schema、权限、风险等级、超时、重试、幂等性和适用数据库方言。

### 6.4 执行预算

所有循环均有上限。初始默认值为 10 次模型调用、20 次工具调用、2 次 SQL 修正、1 次重新规划、120 秒运行时间和 10,000 行最大结果。具体值通过配置和评测调整。

## 7. 语义数据架构

采用双层模型：企业物理数据库通过版本化映射绑定到平台标准语义模型。Agent 主要使用稳定的语义概念和指标 ID，而不是直接猜测物理字段。

首发质量领域包含工厂、车间、产线、产品、工单、批次、工序、设备、检验、检验项目、缺陷、缺陷类型和处置记录等最小业务实体。

指标定义包括公式、聚合方式、单位、支持维度、时间粒度、约束、别名、适用与不适用场景、版本和发布状态。只有经过人工确认且数据字段齐全的指标才能成为可信指标。

未知数据源接入流程：

```text
确定性元数据扫描
→ 安全采样与统计
→ 模型生成候选语义解释
→ 管理员确认物理映射
→ 指标可行性检查
→ 验证查询和数据质量检查
→ 发布给 Agent
```

常见分析优先通过语义查询编译器生成参数化 SQL；语义层无法表达时才使用模型生成的探索性 SQL，并在界面明确标识可信等级。

## 8. SQL 与分析执行

SQL 流程：

```text
查询草案
→ SQLGlot AST 解析
→ 只读、对象权限和函数策略检查
→ 行级过滤注入
→ 行数和超时限制
→ EXPLAIN/成本检查
→ 只读连接执行
→ 结果脱敏与摘要
→ 证据记录
```

高频分析封装为确定性工具，包括描述统计、同比环比、趋势、排行、相关性、缺失分析和 Isolation Forest 异常检测。高级自定义分析进入无网络、无数据库凭证、资源受限的一次性容器沙箱。

## 9. 结果验证与证据

验证分为结构、数据和语义三层：

- 结构：Schema、字段、SQL、依赖和图表配置；
- 数据：空结果、值域、分母、样本量、时间连续性和聚合粒度；
- 语义：指标口径、用户要求、比较周期、数字引用、相关与因果、百分比与百分点。

最终结论必须关联指标定义、语义映射版本、查询计划、已验证 SQL、查询结果摘要、分析工具和执行时间。验证失败时不得直接输出确定性结论。

## 10. 产品交互

主要页面包括智能问析、数据源、语义与指标、分析任务、评测与审计。

问析工作台默认面向业务人员展示问题、计划摘要、执行进度、表格、图表和结论；SQL、工具参数、完整 Trace 和证据按需展开。管理员通过独立页面完成数据接入、语义确认、指标发布和权限配置。

前端通过 SSE 订阅标准事件，包括任务开始、意图解析、语义绑定、计划创建、步骤开始、工具调用、验证警告、用户确认、答案流式输出和任务完成。

## 12. 模型接入原则

DeepSeek V4 Pro 是首选运行模型。Model Gateway 提供结构化生成、工具选择、文本流式输出、重试、降级和调用记录接口。业务代码不直接依赖供应商 SDK。

意图识别使用非思考模式和严格结构化输出；复杂规划、SQL 修正使用思考模式；工具参数使用严格 JSON Schema；解释与报告根据复杂度选择推理强度。所有响应进行 Schema 校验、空响应处理和错误分类。

## 13. 安全设计

- 数据库内容、注释、上传文件均视为不可信输入；
- 外部数据不得改变系统策略或创建工具；
- 查询前强制执行服务端权限和安全策略；
- 敏感字段在进入模型前脱敏；
- 大结果只向模型提供摘要和必要样本；
- 数据库凭证加密且不进入日志；
- 导出和沙箱操作按风险要求确认；
- 对 CTE 写操作、系统表、危险函数、资源消耗和越权关联做专项防护；
- 每次模型与工具调用保留可审计记录。

## 14. 错误处理与降级

错误按模型、语义、策略、查询、结果、沙箱和数据源分类。业务用户收到可行动说明，完整堆栈只进入内部日志。

模型限流和短暂网络错误允许幂等重试；SQL错误最多受控修正两次；语义歧义请求用户确认；图表失败时保留表格和结论；报告失败时保留分析产物；不可恢复的权限和安全错误立即终止。

## 15. 评测体系

首版建立至少 140 组场景：60 条标准问题、20 条多轮对话、20 条歧义问题、20 条异常数据问题和 20 条越权或攻击问题。

指标包括意图、语义绑定、计划、工具选择、SQL执行、结果正确性、数字一致性、安全拒绝、多轮保持、延迟和成本。结果与数字使用确定性断言，语言质量才使用人工或模型评分。

## 16. 工程质量

代码合并门禁包括格式、静态类型、单元测试、集成测试、前端测试、迁移检查、API契约、安全扫描、Agent回归评测和镜像构建。

关键架构规则自动检查：API层不得直接调用模型SDK；Agent节点不得直接访问企业数据库；工具不得绕过Policy Engine；业务模块不得依赖具体模型供应商；指标查询必须记录语义模型版本。

## 17. 交付里程碑

1. 平台骨架：用户、工作空间、权限、数据源和容器化环境；
2. 语义数据底座：元数据扫描、物理映射、指标中心和质量样例库；
3. Agent 核心闭环：意图、规划、工具路由、SQL、验证和多轮对话；
4. 产品增强：图表、报告、审计、评测、异常检测和沙箱；
5. 比赛与产品交付：性能、安全、部署包、测试报告、方案、PPT和演示视频。

## 18. 成功标准

用户能够连接一套未写死结构的制造业质量数据库，系统扫描并辅助建立语义映射；用户通过自然语言提出质量问题，Agent基于已发布指标形成计划，安全调用查询和分析工具，输出表格、图表、结论和证据；用户能够连续追问、查看执行过程并导出报告。

系统同时通过标准、歧义、异常和安全评测，能够说明每次答案使用的数据、指标版本、工具和验证过程。
