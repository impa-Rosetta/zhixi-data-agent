# M7 多轮会话与交互式分析设计规格

- 状态：待用户书面复核
- 日期：2026-09-15
- 前置阶段：M6.2 自然语言会话呈现层
- 范围：持续会话、多轮上下文、轮次排队、结果内联呈现、推荐追问，以及后续图表工具的稳定接入边界

## 1. 背景

当前系统以 `AnalysisRun` 为页面和执行主对象。运行处于澄清状态时可以追加消息，但运行完成、永久失败、取消或越界后，用户必须发起新的分析。这种设计满足了单次运行的持久化、恢复和审计要求，却没有形成用户期望的连续 Agent 交互。

本阶段将用户概念从“反复创建分析任务”升级为“在一个会话中持续追问”。每次提问仍然创建一个不可变、可审计的分析运行，前端不再把这些运行表现为彼此割裂的新聊天。

## 2. 目标与完成定义

### 2.1 目标

- 每次 Agent 回答后，用户都能在当前会话继续提问；
- 成功、澄清、失败、取消、权限不足和越界状态均不关闭会话输入能力；
- 追问能够安全继承上一轮指标、维度、时间、过滤、比较方式和验证结果引用；
- 新主题能够在同一会话自动切换，并清除不相容的旧条件；
- 每一轮拥有独立 AnalysisRun、计划、工具调用、产物、证据和验证记录；
- 用户看到连续消息，审计员看到不可变轮次和运行链路；
- 为趋势、排行、对比、解释、交互式图表和报告提供稳定的会话边界。

### 2.2 完成定义

首次问题、连续追问、主题切换、澄清续答、失败后继续、运行中排队、刷新恢复和 Worker 重启恢复均通过自动化与真实链路验收。任何仅在前端拼接历史消息、没有独立运行与证据的实现不计为完成。

## 3. 方案选择

### 3.1 不采用：复用同一个 AnalysisRun

重新打开完成状态并覆盖上下文会破坏不可变证据、状态机语义、幂等边界和运行级预算，排除。

### 3.2 不采用：前端隐藏多个独立任务

仅在页面把多个 AnalysisRun 拼成聊天，后端没有会话聚合、继承规则和排队顺序，刷新、并发和 API 消费者会产生不一致，排除。

### 3.3 采用：Conversation + Turn + AnalysisRun

`AnalysisConversation` 是用户可见的持续会话，`AnalysisTurn` 是有序的问答轮次，`AnalysisRun` 是该轮不可变的执行实体。会话负责顺序、继承上下文和当前主题；运行继续负责计划、预算、检查点、工具、产物和证据。

## 4. 领域模型

### 4.1 AnalysisConversation

建议字段：

- `id`、`workspace_id`、`created_by_user_id`；
- `title`：由首次问题确定性截断生成，后续可编辑；
- `status`：`active` 或 `archived`；
- `context`：经过白名单约束的当前业务上下文；
- `active_turn_id`：当前执行或等待用户回复的轮次；
- `last_turn_sequence`：单调递增的轮次序号；
- `version`：乐观锁版本；
- `created_at`、`updated_at`、`archived_at`。

会话不保存凭据、SQL、模型推理、异常堆栈或大结果。

### 4.2 AnalysisTurn

建议字段：

- `id`、`workspace_id`、`conversation_id`；
- `sequence`：会话内唯一、从 1 递增；
- `parent_turn_id`：该轮直接引用的上一轮；
- `analysis_run_id`：一对一关联不可变执行运行；
- `relation`：`continue`、`refine`、`explain`、`compare` 或 `switch_topic`；
- `status`：`queued`、`running`、`waiting_for_user`、`completed`、`failed`、`cancelled`；
- `context_before`、`context_after`：安全业务上下文快照；
- `created_at`、`started_at`、`finished_at`。

用户消息和 Agent 消息继续写入现有消息表，并关联本轮 AnalysisRun。投影层按 Turn 顺序聚合消息、产物和证据。

### 4.3 AnalysisRun 兼容扩展

`AnalysisRun` 增加可空 `conversation_id` 和 `turn_id`。新会话产生的运行必须填写；历史运行保持可读。首次访问历史运行时，API 返回一个只读的单轮兼容会话投影，不在读取请求中写数据库。

## 5. 会话上下文契约

### 5.1 允许继承

- 已解析指标键和用户可见指标名称；
- 已解析维度键；
- 时间范围与时间粒度；
- 业务过滤条件；
- 比较方式和排序意图；
- 已发布语义模型 ID 与版本引用；
- 最近一次通过验证的 Artifact ID、Evidence ID 和安全结果摘要；
- 上一轮关系类型和主题摘要。

### 5.2 禁止继承

- 数据源凭据、连接串和 API Key；
- SQL 原文、未经验证的查询和任意代码；
- 模型 `reasoning_content` 或内部推理；
- 原始异常、堆栈和供应商响应；
- 未授权对象、敏感原值和其他工作空间信息；
- 已过期、已撤销或不再发布的语义候选。

### 5.3 上下文大小与版本

会话上下文使用严格 Pydantic 契约，禁止自由 JSON 无限增长。只保存最近一个有效主题和最近一个已验证结果引用；完整历史通过 Turn 查询，不重复塞入模型上下文。上下文包含版本号，后续字段变更通过显式迁移处理。

## 6. 追问分类与 Intent 构建

每条新消息先分类为以下关系：

- `continue`：沿用当前目标继续查询；
- `refine`：修改指标、维度、时间、过滤、粒度或输出形式；
- `explain`：解释上一轮已验证结果或限制；
- `compare`：在已有指标和范围上增加比较；
- `switch_topic`：进入不相关的新目标并清除冲突上下文。

分类输出采用严格结构化契约。确定性规则优先处理明确表达，例如“换成”“按月”“与上月相比”“为什么”和能力/目录问题；其余交给 Model Gateway。模型只能提出关系和 ContextPatch 候选，本地代码负责白名单校验、语义解析、权限检查和最终合并。

无法唯一判断延续或换题时，创建等待用户回复的轮次，由 Agent 自然询问一次。不得静默混合两个冲突主题。

主题切换产生 `conversation.topic_switched` 事件，并在 Agent 回答上方展示轻量提示；它不创建新的用户可见会话。

## 7. 轮次状态与排队

### 7.1 单会话串行

同一会话最多一个 Turn 处于 `running` 或运行内部等待确认状态。用户在运行期间仍可发送消息，新消息创建为 `queued` Turn，但不立即解析上下文；它必须在前一轮进入稳定状态后，基于最新 `context_after` 开始。

### 7.2 等待用户回复

澄清是当前 Turn 的内部续答，用户回答继续同一个 AnalysisRun，不创建新 Turn。完成、永久失败、可重试失败、取消和越界之后的新问题创建下一 Turn。

### 7.3 失败与取消

某一轮失败不关闭 Conversation。失败轮不更新有效结果引用，但保留安全的意图字段供用户修正。取消只取消活动运行；已经排队的后续轮次保持排队，除非用户逐项取消或归档会话。

### 7.4 幂等与并发

- 创建会话、发送消息和澄清续答均要求幂等键；
- `(conversation_id, sequence)` 唯一；
- Conversation 版本承担并发写乐观锁；
- Outbox 只为已成为活动轮次的 AnalysisRun 派发执行事件；
- Worker 完成一轮后以事务方式更新 Turn、Conversation 上下文并激活下一排队轮；
- 重复事件不得生成重复 Turn、运行或 Agent 消息。

## 8. API 与投影

新增以会话为中心的 API：

- `POST /workspaces/{workspace_id}/analysis-conversations`：创建会话并提交首条消息；
- `GET /workspaces/{workspace_id}/analysis-conversations`：分页列出会话；
- `GET /workspaces/{workspace_id}/analysis-conversations/{id}`：读取会话元数据；
- `GET /workspaces/{workspace_id}/analysis-conversations/{id}/view`：读取有序轮次投影；
- `POST /workspaces/{workspace_id}/analysis-conversations/{id}/messages`：发送下一轮或当前澄清回复；
- `POST /workspaces/{workspace_id}/analysis-conversations/{id}/turns/{turn_id}/cancel`：取消活动轮；
- `GET /workspaces/{workspace_id}/analysis-conversations/{id}/events/stream`：会话级可重放 SSE。

现有 AnalysisRun API 保留，供审计、兼容和运行级诊断使用。前端业务视图切换到 Conversation API，技术详情仍通过 `analysis_run_id` 定位原运行。

会话 SSE 事件带 `conversation_sequence`、`turn_id`、`turn_sequence` 和可选 `run_event_sequence`。断线恢复以会话序号为准，避免在多个运行游标之间产生空洞。

## 9. 前端交互

### 9.1 会话列表

左栏由运行列表改为会话列表，展示标题、最近消息摘要、更新时间和当前状态。单次运行不再占用一个列表项。保留“新建会话”操作，用于用户主动清空上下文。

### 9.2 连续消息流

- 按 Turn 展示用户消息、Agent 消息和该轮产物；
- 表格、指标卡、图表和限制说明作为 Agent 消息附件内联；
- 每个回答提供“数据依据”，展开后定位该轮 Evidence、Validation、查询和冻结版本；
- 主题切换以轻量分隔提示展示；
- 排队消息显示队列位置，运行消息显示当前节点；
- 历史轮次保持可浏览，不被最新结果替换。

### 9.3 始终可用的输入框

输入框在会话 active 状态下始终可用：

- 空闲时显示“继续追问”；
- 当前轮澄清时显示“回复 Agent”；
- 当前轮执行时允许发送并标记为排队；
- 永久失败、取消、权限不足和越界后仍允许发送下一问题；
- 会话归档后只读，用户可新建会话但不能继续写入。

### 9.4 推荐追问

每个稳定回答最多提供三个可执行建议。建议由本地能力、当前指标、语义模型支持维度和结果形状确定性生成，例如：

- 单值指标：时间趋势、按可用维度比较、查看口径；
- 趋势结果：最高/最低周期、环比变化、异常点；
- 排行结果：查看头部对象趋势、贡献占比、筛选对象；
- 目录结果：查看字段、选择指标、查看数据源范围；
- 不可执行结果：仅推荐当前数据真正支持的替代分析。

建议按钮发送普通用户消息，必须重新经过追问分类、Policy Engine 和工具执行。模型可以调整文案，但不能推荐未注册或不可执行的能力。

## 10. 交互式图表接入边界

本规格先建立图表作为 Turn 附件的契约，具体统计与 ECharts 实现在后续 M7 切片完成。

图表输入只能引用已验证 Artifact，输出受限 `ChartSpec`，包含图表类型、字段映射、标题、单位、排序、截断和 Evidence 引用。允许的首批类型为折线、柱状、横向排行柱、堆叠柱和散点；不接受任意 JavaScript、HTML、回调函数或网络资源。

用户切换图表类型、系列或可用维度属于本地视图交互，不重新查询；改变指标、时间、过滤或比较条件必须创建新 Turn 并重新执行。图表失败只影响附件，不删除表格、回答或证据。

## 11. 权限与安全

- Conversation、Turn、Run、Message 和 Artifact 均校验同一 `workspace_id`；
- 发送每条消息时重新执行工作空间角色授权；
- 数据访问和工具执行在每个新 Run 中重新鉴权，不沿用旧权限结论；
- 用户失去会话读取权限后，不能通过已知 ID 获取消息或证据；
- 主题切换、排队和推荐追问不能绕过 Tool Registry；
- 模型只接收最小安全上下文，不接收整个会话数据库记录；
- 用户可见错误遵循 M6.2 自然语言呈现层，内部码仅在授权技术详情中展示；
- 日志、SSE 和前端状态不得包含密钥、凭据、敏感原值和内部推理。

## 12. 恢复与兼容

- 页面刷新从 Conversation View 恢复所有轮次和活动状态；
- SSE 断线按会话序号重放；
- Worker 重启后从活动 AnalysisRun 检查点恢复，Conversation 不自行重算；
- 服务完成活动轮次但尚未激活下一轮时，由恢复任务根据事务状态安全补发；
- 老的 `/app/analysis/{run_id}` 链接继续可访问，并显示单轮兼容视图；
- 新入口使用 `/app/conversations/{conversation_id}`；
- 不批量改写历史运行，不删除现有 API。

## 13. 错误处理

- 追问关系歧义：自然澄清；
- 历史 Artifact 不存在、过期或不再授权：说明失效原因并询问是否重新查询；
- 语义版本不再发布：新轮重新绑定当前发布版本，同时明确口径变化；
- 新权限拒绝：不读取数据，以自然语言说明可行动步骤；
- 排队激活失败：保持 queued 并由恢复任务重试，不重复创建运行；
- 模型暂态故障：保留当前 Turn 检查点和后续排队消息；
- 图表或报告失败：保留已经验证的回答、表格与 Evidence；
- 未知内部错误：返回安全通用说明和关联 ID，不返回堆栈。

## 14. 实施切片

### M7.1 会话领域与兼容投影

新增 Conversation、Turn、迁移、领域服务、API 和历史单轮兼容投影。

### M7.2 多轮继承与主题切换

实现关系分类、白名单上下文、跨运行 Intent 构建、主题切换和自然澄清。

### M7.3 串行排队与恢复

实现单会话活动轮、排队激活、Outbox 事务、取消语义、Worker 恢复和幂等测试。

### M7.4 连续会话前端

将运行列表升级为会话列表，交付始终可用输入框、轮次内联产物、状态与主题提示。

### M7.5 推荐追问与双端验收

实现确定性推荐引擎，并完成真实 DeepSeek、数据库、工具、Evidence、桌面和移动端验收。

### M7.6 统计与交互式图表

在上述会话边界上实现趋势、排行、对比、描述统计和受限 ChartSpec/ECharts 附件。

### M7.7 报告组装

从已验证的多轮 Artifact 组装 Markdown、HTML 和 PDF 报告，不重复查询或计算。

## 15. 测试与验收

### 15.1 自动化测试

- Conversation/Turn 唯一约束、乐观锁、工作空间隔离和迁移往返；
- continue/refine/explain/compare/switch_topic 的确定性和模型结构化契约；
- 上下文白名单、清理规则、大小限制和禁止字段；
- 同会话串行、并发发送、重复幂等键、Outbox 重投和 Worker 恢复；
- 成功、澄清、失败、取消、权限不足和越界后的继续发送；
- 历史单轮兼容、会话 SSE 重放和未知事件兼容；
- 推荐追问只包含当前可执行能力；
- 前端桌面、390px 移动端、键盘操作和无横向溢出。

### 15.2 真实纵向场景

1. 首轮“不良率是多少”返回可信结果；
2. 追问“按月份展开”继承指标并生成趋势；
3. 追问“哪个月最高”继承时间范围并执行排行/摘要；
4. 追问“为什么”引用上一轮 Artifact 和 Evidence；
5. 问“数据库里有哪些表”切换主题并显示提示；
6. 在运行期间连续发送两条消息，按顺序执行且不重复；
7. 在映射缺失、权限拒绝和越界回答后继续提出可执行问题；
8. 刷新、SSE 断线和 Worker 重启后恢复同一会话；
9. 桌面和移动端均能浏览历史轮次、继续追问和定位证据。

## 16. 非目标

- 不把整个聊天记录直接发送给模型；
- 不允许并行轮次共享可变上下文；
- 不在本阶段引入任意前端脚本图表；
- 不允许推荐按钮绕过 Agent 与 Policy Engine；
- 不批量迁移或删除历史 AnalysisRun；
- 不在 M7.1 至 M7.5 阶段提前实现 PDF 报告或开放式 Python 沙箱。
